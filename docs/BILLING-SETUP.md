# 스카이야드 심화 이용권 결제 연결

2026-09-10 · 구현 및 운영 설정 안내. **9,900원 일회성 상품의 앱·서버 코드는 구현했으며 현재 앱은 판매 전 베타 미리보기다.** Play 상품 등록, Google 구매 검증 자격 증명 설정, 결제용 마이그레이션·`purchases` 서버 배포와 환불 재검증 스케줄러, 일반 가입용 SMTP는 아직 완료하지 않았다. 실제 판매 전환, 무료 권한 발급, Play 라이선스 구매·실결제는 실행하지 않았다. 기존 커뮤니티 서버의 운영 여부와 새 결제 서버의 미배포 상태는 별개다.

## 상품과 현재 베타

사용자가 확정한 상품은 **9,900원 1회 구매**다. 난이도 2·3 심화 퀴즈, 역사·천체물리 문제와 힌트, 망원경 학습 코스를 한 묶음으로 제공한다. 상품 ID는 `skyard_plus_lifetime`, Google Play의 **비소비성 일회성 상품**, 구매 옵션 ID는 `buy`로 맞춘다. 구독·대여·선주문·소모품·다중 수량 구매를 사용하지 않는다. 상품 ID와 구매 옵션은 Console에서 아직 등록하지 않았다.

기본 하늘 지도·관측 도구·시야원·기록·백업·기존 획득 보상은 구매와 무관하다. 난이도 1 퀴즈와 맨눈·쌍안경 코스는 무료이며, 무료 코스에 지정된 확인 문제는 난이도 2·3이어도 그 코스 안에서 풀 수 있다. 망원경용 시야원 같은 기본 관측 도구와 유료 망원경 학습 코스를 구분한다. 권한 검사 모듈은 기존 기록이나 보상을 삭제·초기화하지 않는다. 혼합 난이도 미션, 복습, 딥링크, 답 저장 등 실제 학습 진입 경계는 학습 통합 코드에서 같은 정책으로 검사한다.

- `VITE_SKYARD_MONETIZATION_MODE`가 정확히 `live`가 아니면 **베타 미리보기**다. 학습 체험을 허용하지만 `hasPlus`를 구매한 것처럼 바꾸지 않으며 구매·복원 네이티브 흐름을 열지 않는다. 로컬 로그인 계정만 확인하고 결제 서버 API를 조회하지 않아, 아직 배포하지 않은 결제 서버의 오류를 베타 화면에 표시하지 않는다.
- `live`에서는 현재 로그인 계정의 서버 권한이 있어야 심화 학습을 연다. 설정 오류·응답 오류로 무료 권한을 자동 부여하지 않는다.
- 새 Play 구매는 서버 준비 확인과 Android의 실제 상품·가격 조회까지 성공해야 시작한다. 금액 표시는 `ProductDetails`가 돌려준 현지 가격을 사용한다. 9,900원 문자열을 실제 결제 견적으로 가장하지 않는다.
- 웹/iOS에는 새 결제 기능을 구현하지 않았다. 서버 연결과 `live` 설정 이후 같은 앱 계정의 서버 권한을 확인하는 코드는 공통으로 제공한다. 현재 `preview`에서는 이 조회도 하지 않는다. Apple에서 판매를 시작하려면 StoreKit·서버 검증·복원과 Apple의 해당 판매 정책을 별도로 완성해야 한다. iOS에서 외부 구매로 유도하는 링크를 추가하지 않는다.

## UI·학습 코드 연결 계약

`src/entitlements/index.ts`에서 다음을 제공한다.

| API                                | 역할                                                                                                                                                        |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `useEntitlements()`                | 현재 계정, `preview/live`, 서버 `hasPlus`, `source`, `validUntil`, 준비 상태, 현지 상품 가격, 오류, 처리 중 상태                                            |
| `getEntitlementsSnapshot()`        | 현재 메모리 스냅샷. 이 값 자체를 로컬 DB에 보관하지 않는다.                                                                                                 |
| `canAccessPlus(snapshot)`          | 베타 미리보기 또는 현재 계정의 유효한 서버 권한인지 판정                                                                                                    |
| `ensurePlusAccess()`               | 실제 학습 시작/답 저장 전에 계정을 다시 확인. 실패는 `PlusAccessError.code`의 `PLUS_REQUIRED` 또는 `ENTITLEMENTS_UNAVAILABLE`로 구분                        |
| `refreshEntitlements()`            | 미리보기에서는 로컬 계정만 확인. `live`에서는 서버 권한·스토어 준비 상태 갱신                                                                               |
| `purchasePlus()` / `restorePlus()` | 사용자 버튼으로 시작. 결과 `status`는 `verified`, `pending`, `cancelled`, `nothing-to-restore`, `unavailable`, `error` 중 하나이며 선택적 `error` 코드 제공 |

`availability`는 `setup-required`, `sign-in-required`, `android-play`, `unsupported-platform` 중 하나다. `restoreAvailable`은 신규 판매 가능 여부와 별도다. 판매를 중지해도 Google 검증 서버가 가동 중이면 기존 구매의 확인·복원은 할 수 있다. `pending`은 결제 완료나 권한 활성화가 아니다. `nothing-to-restore`는 현재 Play 계정에서 해당 비소비 구매를 찾지 못했다는 뜻이다.

비동기 검사는 IndexedDB 트랜잭션 **전에** 끝낸다. 로그인 계정 변경 이벤트에서 이전 권한·가격을 먼저 비우고, 오래된 구매/서버 응답은 현재 계정에 적용하지 않는다. 결제 중 로그인 계정을 바꾸면 해당 구매를 다른 계정에 옮기지 않는다. 원래 앱 계정으로 돌아가 복원한다.

## 서버 검증과 환불

마이그레이션 `202609100002_entitlements.sql`은 기존 커뮤니티와 별도인 네 테이블을 만든다. 일반 사용자와 익명 사용자는 구매 토큰·무료 부여 테이블을 직접 읽거나 쓸 수 없고, 권한 부여 RPC도 호출할 수 없다. Edge Function `purchases`가 로그인 JWT를 `getUser`로 확인한 뒤 서비스 역할로 접근한다.

1. `prepare`: 현재 사용자용 무작위 64자리 계정 식별자를 발급한다. 이메일·공개 이름을 Play에 보내지 않는다. Android는 이를 `setObfuscatedAccountId`로 결제에 첨부한다.
2. `verify`: 클라이언트 토큰을 고정 패키지의 Google `purchases.productsv2.getproductpurchasev2`로 조회한다. 상품 ID·`buy` 옵션·계정 식별자·수량·비소비 상태·구매 상태를 확인한다.
3. Google이 완료 구매를 반환하면 토큰을 한 계정에 예약한다. 미승인 구매에는 권한을 주지 않는다. 서버에서 acknowledge를 호출한 뒤 다시 Google을 조회하고 승인된 완료 구매만 활성화한다. 네이티브는 consume나 acknowledge를 호출하지 않는다.
4. 대기는 대기로 저장하며 완료로 간주하지 않는다. 취소·전액 환불은 취소로 저장한다. 토큰 해시의 고유성·트랜잭션 잠금으로 중복 복원과 계정 이동을 막고, 취소된 토큰을 늦게 도착한 성공 응답으로 되살리지 않는다.
5. 계정 조회는 마지막 검증 후 15분이 지난 구매를 재확인한다. 별도 `reconcile` 작업은 미확인/오래된 구매를 계속 확인한다. API 장애는 승인이나 환불로 추측하지 않는다.

서버 확인 권한의 최대 유효기간은 **24시간**이다. 구매 자체가 24시간 뒤 소멸하는 것은 아니며, 환불·계정 상태를 확인하기 위한 갱신 시간이다. 이번 구현은 권한을 메모리에만 두므로 앱 완전 종료·재시작 후에는 다시 온라인 확인이 필요하다. **장기간 오프라인 유료 이용은 아직 지원하지 않는다.** 기본 오프라인 관측과 내 기록은 이 제한을 받지 않는다. 향후 오프라인 권한을 늘리려면 계정·만료시간이 포함된 서버 서명 증서를 검증해야 하며 로컬 `isPro` 값으로 대체하면 안 된다.

계정 삭제는 무료 부여·무작위 식별자와 계정 연결을 지우되 구매 토큰의 귀속 흔적은 다른 계정의 자동 재사용을 막기 위해 소유자 없는 상태로 남긴다. 같은 이메일로 새로 만든 계정을 기존 구매 계정으로 자동 취급하지 않는다. 판매 전 구매 기록·세무/분쟁 대응 보관 기간과 삭제 문의 절차를 개인정보 안내에 확정해야 한다. 원시 토큰은 재검증에 필요한 민감한 자격 정보로 취급하며 앱 로그·일반 API 응답·백업·스크린샷·Git에 넣지 않는다.

## 판매 전에 필요한 외부 설정

1. Play Console에서 해당 패키지의 `skyard_plus_lifetime` / `buy`를 등록·활성화하고 한국 기본 가격 9,900원과 판매 국가를 확인한다. 유효한 Play 서명 AAB를 테스트 트랙에 올리고 라이선스 테스터와 설치 경로를 준비한다.
2. Google Cloud의 Android Publisher API와 전용 서비스 계정을 마련하고 해당 Play 앱의 구매 조회·주문 관리에 필요한 권한을 부여한다. 서비스 계정의 비공개 키를 VITE 변수나 앱 패키지에 넣지 않는다.
3. Supabase에 마이그레이션과 `purchases` 함수를 배포한다. 함수 안에서 JWT를 검증하므로 배포 시 플랫폼의 기존 JWT 검증 설정과 새 공개 키 형식의 호환성을 확인한다. `reconcile`의 사용자 JWT 대신 별도 인증을 허용하려면 함수 플랫폼 JWT 검증은 끄고 **이 함수 자체의** `getUser`/비밀 검증을 유지한다. 커뮤니티 함수의 인증 설정을 전역으로 완화하지 않는다.
4. 서버 환경에 `SKYARD_GOOGLE_SERVICE_ACCOUNT_JSON`과 무작위 32자 이상의 `SKYARD_BILLING_RECONCILE_SECRET`을 안전하게 설정한다. `SKYARD_BILLING_ENABLED` 기본은 false다. 테스트 구매를 검증할 격리 환경에서만 `SKYARD_BILLING_ALLOW_TEST_PURCHASES=true`를 명시한다. 테스트 구매는 DB에서 표시되며 기본 서버는 이를 거부한다.
5. 비밀을 서버에서만 보내는 스케줄러가 `POST /functions/v1/purchases?action=reconcile`을 `x-skyard-reconcile` 헤더로 정기 호출하도록 설정한다. 최초 운영은 5분 주기부터 시작하되 처리량과 함수 시간 제한에 맞게 조정한다. 결과는 처리/성공/실패 숫자만 반환한다. 미완료 배치와 실패를 감시하고 24시간 확인 공백이나 3일 내 승인 실패가 생기지 않게 운영한다. **비밀 변수가 존재한다는 것만으로 스케줄러가 설정됐다고 판단하지 않는다.** RTDN/Pub/Sub push 연결은 이번 코드에 포함하지 않았다.
6. 일반 가입 메일 SMTP·원래 구매 계정 복귀·운영 담당자·심사 계정 접근을 준비한다. 현재 일반 이메일 발송은 별도 미완료 사항이다. 구매를 위해 로그인이 필요한데 일반 로그인을 못 하는 상태로 판매하지 않는다.
7. 외부 설정이 준비되면 **라이선스 테스터만 대상으로 하는 별도 결제 검증 환경**에서 서버 판매 플래그와 프런트 `live` 모드를 켠다. `preview` 상태에서는 결제 API 자체를 호출하지 않으므로 구매·복원 시험을 할 수 없다. 테스트 결제 수단으로 완료·사용자 취소·대기 후 완료/취소·결제 중 앱 종료·중복 복원·다른 앱 계정·환불·서버 장애·계정 삭제를 확인한다. 차지백 등 해당 테스트 수단으로 재현하지 못한 항목은 별도 미확인으로 남긴다. 테스트 구매와 운영 권한을 분리하고 검증이 끝난 뒤에만 일반 판매용 서버·`live` 빌드를 활성화한다.

일반 내부·비공개 테스터와 **라이선스 테스터는 별도 설정**이다. 현재 베타는 일반 앱 사용·학습 체험용이며 구매 시험용이 아니다. 판매가 가능한 빌드에서는 일반 테스터에게도 실제 금액이 청구될 수 있으므로, 결제 검증은 라이선스 계정과 Google 테스트 결제 수단을 확인해 진행한다. 라이선스 테스터 등록은 앱 계정에 영구 Plus를 주는 절차가 아니다. [공식 Billing 테스트 안내](https://developer.android.com/google/play/billing/test)

Google Billing은 완료 구매를 3일 안에 승인하지 않으면 환불할 수 있으며 대기 중에는 승인하지 않는다. 서버 검증과 계정 식별자 연결도 공식 보안 권장 사항에 따른다. [Billing 통합 및 대기 구매](https://developer.android.com/google/play/billing/integrate), [구매 보안](https://developer.android.com/google/play/billing/security)

## 본인·여자친구 무료 권한

관리자만 실행할 수 있는 `sky_set_plus_grant(p_owner,p_operator,p_reason,p_revoke)`를 준비했다. 앱의 구매 상태를 위조하지 않고 `source='grant'`인 권한으로 구분한다. 서버 배포 후 두 사람의 실제 Auth UUID와 계정 소유가 확인되면 운영자가 각각 **만료일 없는 무상 권한**(`expires_at=null`)을 부여할 수 있다. **이번에는 실제 UUID를 확인하거나 권한을 발급하지 않았다.** 이 권한도 계정 삭제·운영자 회수는 가능하며, 앱에서 받은 24시간 확인 유효기간은 무상 이용권 자체의 만료일이 아니다. 이메일 문자열 하드코딩, 첫 가입자 운영자 승격, 숨은 Pro 스위치, 구매 영수증 없이 `play`로 표시하는 우회는 없다.

서버 연결과 `live` 설정 후 같은 앱 계정으로 접속하면 Android와 iPhone PWA에서 해당 서버 부여 권한을 조회할 수 있다. 현재 미리보기 체험을 실제 무상 권한 발급으로 표시하지 않는다. Google Play 계정의 구매 소유와 앱 로그인 계정을 임의로 바꾸지 않는다. 현재 grant 행에는 담당자·사유·부여/회수 시각이 남으며, 운영 감사 이력의 장기 보관 체계는 판매 전 운영 정책과 함께 정한다.

## 검증 범위와 남은 일

단위 검사는 가짜 서버 성공 응답이 실제 권한이 되는 구현을 만드는 것이 아니라, 네이티브 완료만으로는 권한이 생기지 않는지·다른 계정의 늦은 응답이 섞이지 않는지·검증/승인 순서와 취소 상태가 유지되는지를 격리된 대체 API로 검사한다. `tests/backend/entitlements.test.mjs`는 실제 PostgreSQL 호환 PGlite에서 테이블/RPC 권한, 한 토큰의 한 계정 귀속, 무료 부여/회수, 삭제 후 재사용 방지를 검사한다. 실제 Supabase나 Google 결제를 수행하는 테스트가 아니다.

Android Billing 9.1.0 브리지는 로컬 Java 릴리스 컴파일을 통과했다. 이 결과는 Play 상품 조회나 결제 성공을 뜻하지 않는다. 이 문서는 Google Play 콘솔 승인, 물리 Android/iPhone 결제, Apple IAP, 환불 스케줄러의 실제 운영 또는 장기간 오프라인 권한 완료를 주장하지 않는다. 최종 서명 빌드와 전체 제품 통합 결과는 별도 최종 빌드 보고를 따른다. 유료 콘텐츠가 정적 앱 팩에 포함된 구조는 서버 구매 검증과 별개로 추출 방지 DRM을 제공하지 않는다.
