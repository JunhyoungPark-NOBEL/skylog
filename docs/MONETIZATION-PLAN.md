# Skylog 유료 출시와 두 사람 무료 이용 계획

> **최신 기준(2026-09-08)**: 전 기능 무료 요청(D-048)으로 이전 유료화 제안은 적용하지 않는다. 구현·서버·검증·남은 개통 절차는 [무료 서비스 구현](FREE-COMMUNITY.md)이 정본이다. 아래는 beta.6 시점의 제안 이력이다.

> 검토일: 2026-09-08. 사용자 요청을 구체화한 **제안**이다. 가격·상품·계정을 생성하거나 결제 기능을 구현한 문서가 아니다. 실제 판매 전 출시 국가와 스토어 계정의 최신 조건을 다시 확인한다.

## 1. 추천: 기존 기능 무료 + 선택형 꾸미기, 이후 클라우드 구독

**2026-09-08 갱신(D-046)**: 앞서 제안한 “기존 망원경/심화 학습을 Pro로 묶기” 대신, 현재 제공하는 관측·코스·퀴즈·기록·백업을 무료로 유지하는 안을 추천한다. 아래는 판매 범위 제안이며 실제 가격/상품을 확정하거나 기능을 잠그지 않았다.

| 범위             | 제안                                                                                                    | 결제 방식                                         |
| ---------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| 기본 이용        | 현재 하늘·날씨·달력·검색·스타호핑·장비·기록/통계·코스·퀴즈·이야기·업적·백업, 기기 내 기록 열람/내보내기 | 무료 유지                                         |
| 기본 꾸미기/소통 | 업적으로 얻는 마당/아바타 아이템, 사진 보기·댓글·반응·신고/차단, 일정량의 압축 사진 공유                | 무료. 서버 기능은 아직 미구현                     |
| 첫 유료 상품     | 야생화 마당·달빛 정원·아바타 의상 등 추가 **외형** 팩                                                   | 팩별 1회 구매. 획득형 아이템·점수와 별개          |
| 이후 Cloud       | 원본 사진 보관 추가 용량, 기기 간 자동 동기화·버전 백업                                                 | 실제 서버 서비스가 생긴 뒤 월/연 구독 1종 검토    |
| 더 먼 후속       | 새로 개발할 고급 관측 계획/자동화·내보내기 도구                                                         | 가치 검증 후 판단. 현재 가이드를 소급 잠그지 않음 |

이 구조는 핵심 경험을 무료로 유지하고 추가 꾸미기를 판매하는 [Finch](https://help.finchcare.com/hc/en-us/articles/37780200600589-Benefits-of-Finch-Plus), 기본 소통과 추가 사진 용량/도구를 구분하는 [AstroBin](https://welcome.astrobin.com/plans-faq) 사례에서 착안했다. 관측 도구를 Plus로 판매하는 [Stellarium Mobile](https://www.stellarium-labs.com/stellarium-mobile-plus/) 사례도 있지만, Skylog는 이미 제공한 기능의 접근성을 유지하는 쪽을 택하는 것이 낫다는 **제품 판단**이다. 공식 비교와 적용하지 않을 부분은 [조사 기록](../plan/research/2026-09-08-community-monetization.md)에 있다.

### 결제 화면이 나타날 때

추가 테마를 미리 보고 구매 버튼을 눌렀을 때만 가격/포함 아이템/1회 구매를 설명한다. 퀴즈 오답·첫 실행·관측 안내 중간에 결제를 끼우지 않는다. 무료로 얻을 수 있는 장식도 같은 화면에서 명확히 표시한다. 유료 재시도·순위 상승·정답·관측 정확도·신고 기능을 팔지 않는다. 유료 회원도 같은 커뮤니티 규칙을 따른다.

클라우드는 무료 용량에 가까워질 때 사용량과 추가 용량을 안내한다. 원본 보관과 공개용 압축 사진의 용량을 구분하고, 무료 압축 공유량이 정기적으로 갱신되는 방안을 비용 측정 후 정한다. 구독 종료 시에도 로컬 기록과 구매한 외형은 유지한다. 클라우드 초과분은 신규 업로드 제한→사전 안내/유예/내보내기 순서로 처리하며 갑자기 지우지 않는다. 정확한 유예 기간과 장기 보관 조건은 운영비/약관을 확정할 때 정한다.

### 가격을 정하는 방법

현재 판매가를 확정하지 않는다. 사용자 인터뷰용 후보로 외형 팩 1,900~4,900원, 클라우드 월 2,900원/연 24,900원 등을 비교할 수 있으나 **시장 평균이나 수익성 검증 가격이 아니다**. 이전 9,900원 Pro 제안도 확정 상품이 아니며 첫 출시안에서 제외한다. 아직 없는 서비스를 선결제시키지 않는다.

서버 비용은 저장 GB뿐 아니라 썸네일 변환·다운로드 전송·DB·날씨 API·신고 검토/고객 지원이 포함된다. 매출 계산에서는 스토어 공제·세금·환불을 실제 계약대로 반영한다. 손익분기 결제 인원은 월 고정비 / (1인 순매출 − 1인 변동비)로 계산하되 분모가 0 이하이면 가격·범위를 다시 검토한다. 무료 사용자 비용도 고정/공통 비용에 포함한다. 용량·매출·운영비가 측정되지 않았으므로 아직 수치를 꾸며 넣지 않는다.

내 마당 반복 이용, 무료 성취 보상 만족도, 장식 미리보기 후 구매 의향, 사진 업로드/전송량, 신고율·처리 시간을 먼저 확인한다. 측정 동의/개인정보 설계 없이 추적 SDK를 붙이지 않는다. 유지율이나 매출 개선을 근거 없이 보장하지 않는다.

## 2. 본인(Android)과 여자친구(iPhone)는 무료로

두 사람 모두 결제 없이 전체 기능을 쓰게 하는 기존 제안은 유지한다. 판매 상품이 꾸미기 팩/클라우드로 바뀌면 상품별 무료 권한으로 적용하고, 클라우드 운영비는 운영자가 부담할 범위를 정한다. 가장 적은 운영 부담으로 출시하려면 **각 스토어의 공식 무료 코드를 각자 계정에 적용**하고, 여러 플랫폼에서 같은 권한을 쓰는 기능은 Skylog 계정과 연결한다.

| 방법                            | 이번 요구에 적용                                                                                             | 제한                                                                                          |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Apple 꾸미기 팩 무료 offer code | 여자친구가 자신의 Apple 계정으로 비소모성 꾸미기 팩을 0원에 획득. 성공 거래를 정상 구매와 같은 흐름으로 처리 | 앱 배포 가능 상태·IAP 승인·코드 사용 조건 필요. 코드 사용 기한과 상품 이용권의 만료는 별개    |
| Google 꾸미기 팩 promo code     | 본인이 자신의 Google 계정으로 한 번 구매 상품을 무료로 획득                                                  | 활성 상품/구매 옵션과 프로모션 설정 필요. Apple이나 PWA로 자동 이전되지 않음                  |
| Skylog 계정 이용권              | 본인과 여자친구에게 별도의 만료 없는 무료 권한을 부여하고 Android·iOS·PWA에 연결                             | 로그인·서버·거래 검증·계정 연결 기능을 새로 만들어야 함. 현재 없음                            |
| Apple 가족 공유                 | 설정한 비소모성 IAP/구독을 Apple 가족 그룹에 공유                                                            | Apple 생태계 안의 기능이며 Android↔iPhone 해결책이 아님. 개발자가 상품에 켠 뒤에는 끌 수 없음 |
| Google 가족 콘텐츠 라이브러리   | 일부 유료 앱 구매 공유                                                                                       | 인앱 구매는 공유 대상이 아니므로 꾸미기 팩 IAP에는 사용 불가                                  |
| TestFlight/결제 샌드박스        | 출시 전 iPhone·구매 흐름 테스트                                                                              | TestFlight 빌드는 최대 90일. 테스트 거래는 정식 앱의 영구 무료 이용권이 아님                  |

Apple은 현재 비소모성 상품을 포함한 모든 IAP 유형의 offer code를 지원한다. 성공적으로 사용하면 구매와 같은 상품 권한을 부여해야 한다. 단순히 무료 앱 다운로드용 코드를 주는 것과 꾸미기 팩 IAP 무료 코드는 다르다. [Apple offer code 구현](https://developer.apple.com/documentation/storekit/supporting-offer-codes-in-your-app), [App Store Connect 설정](https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/create-offer-codes-for-in-app-purchases)

Google은 유료 앱·한 번 구매 상품·구독용 프로모션을 제공한다. 구독 코드는 무료 기간 뒤 결제로 이어질 수 있으므로 두 사람에게는 구독 체험보다 **비소모성 Pro 무료 획득**을 권한다. [Google 프로모션](https://support.google.com/googleplay/android-developer/answer/6321495?hl=en)

가족 공유와 테스트의 제약은 공식 안내를 따른다. [Apple 가족 공유](https://developer.apple.com/help/app-store-connect/configure-in-app-purchase-settings/turn-on-family-sharing-for-in-app-purchases), [Google 가족 콘텐츠 라이브러리](https://support.google.com/googleplay/answer/7007852?hl=en), [TestFlight 90일](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview), [Apple 테스트 결제](https://developer.apple.com/documentation/storekit/in-app_purchase/testing_in-app_purchases_with_sandbox)

두 사람의 비밀번호나 Apple/Google 계정을 공유할 필요는 없다. 각자 자기 계정을 사용한다. 향후 본인에게 `owner`, 여자친구에게 `complimentary` 이용권을 부여하되 **여자친구에게 운영 관리자 권한을 주는 것은 아니다**. 새로운 유료 기능도 두 사람에게 무료로 제공하려면 상품이 추가될 때 무료 권한의 기능 목록을 함께 갱신한다.

## 3. Android·iOS·웹의 결제 경로

- Google Play 앱에서 디지털 기능을 판매하는 기본 경로는 **Google Play Billing**이다. 해당 앱에서 외부 웹 결제로 유도하는 동작은 정책 예외·프로그램 자격을 별도로 충족해야 한다. [Google 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)
- App Store 앱의 기능 해금 기본 경로는 **StoreKit 인앱 구매**다. 여러 플랫폼에서 얻은 기능을 계정으로 공유하려면 iOS에서도 같은 상품을 IAP로 제공하는 방식으로 설계한다. 자체 라이선스 키·숨은 해금 동작으로 인앱 구매를 대체하지 않는다. [Apple 심사 지침 3.1.1·3.1.3(b)](https://developer.apple.com/app-store/review/guidelines/)
- Safari/브라우저에서 쓰는 독립 PWA의 결제는 웹 결제 사업자와 서버로 별도 구성할 수 있다. **PWA 구매와 스토어 앱 내 웹 결제 버튼은 구분**한다. 웹 판매 기능을 만들었다고 모든 국가의 네이티브 앱에 그 버튼을 넣을 수 있는 것은 아니다. Google은 다른 곳에서 구매한 상품을 로그인해 사용하는 모델도 설명한다. [Google 결제 정책 설명](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en)
- 한국·미국·EU·일본 등의 외부 결제/링크 제도는 서로 다르다. 예를 들어 Apple의 한국 제도는 별도 권한·한국 전용 배포·결제 사업자·심사를 요구한다. 초기 출시에서는 복잡도를 줄이기 위해 양쪽 표준 인앱 구매를 권한다. [Apple 한국 외부 결제](https://developer.apple.com/support/storekit-external-entitlement-kr/)

운영자가 대가 없이 주는 계정 권한도 심사에서 이해할 수 있도록 설명한다. **비밀 버튼이나 공용 비밀번호로 전체 해금하는 방식은 만들지 않는다.** 정식 네이티브 무료 제공에는 먼저 공식 무료 거래를 사용하고, 그 거래를 서버 계정에 연결하면 복원과 검증이 명확하다. 서버의 수동 무료 권한을 네이티브에서도 인정하는 운영안은 심사 설명에 공개하며, 심사 승인을 미리 보장하지 않는다.

## 4. 구현 설계와 기록 보존

아래는 구현할 때의 설계안이다. 현재 서버/계정/이용권이 준비되어 있다는 뜻이 아니다.

1. **기존 사용을 유지한다.** 기본 탐색은 로그인 없이 허용한다. 구매·무료 권한 연결·기기 간 이용권 복원 시점에 Skylog 계정을 연결한다. 구매 직전 다른 계정에 잘못 연결되지 않도록 현재 계정을 보여준다.
2. **서버에 거래와 권한을 구분해 저장한다.** `accounts`, `store_transactions`, `entitlements`, `grant_audit`를 제안한다. 이용권은 `account_id`, 기능, 출처(`apple`, `google`, `web`, `owner`, `complimentary`), 상태, 만료일, 갱신 시각을 가진다. 두 사람의 무료 권한에는 만료일을 두지 않고 누가 언제 부여했는지 기록한다. 실제 계정 ID·이메일·상품 ID는 아직 미정이다.
3. **거래를 검증한 뒤 해금한다.** Apple 거래 서명·상품·앱·환경과 서버 알림, Google 구매 토큰·상품·앱·결제 상태와 알림을 검증한다. 중복 알림은 같은 결과가 되도록 처리하고, 대기 중 결제를 완료로 취급하지 않는다. Google 비소모성 상품은 승인(acknowledge)하되 소비(consume)하지 않는다. [Apple 서버 API](https://developer.apple.com/documentation/appstoreserverapi), [Google 구매 통합](https://developer.android.com/google/play/billing/integrate), [Google 구매 보안](https://developer.android.com/google/play/billing/security)
4. **무료 권한도 서버에서 부여한다.** 클라이언트가 보낸 `isPro`, 이메일 문자열, 로컬 설정, JSON 백업 파일을 권한의 증거로 신뢰하지 않는다. 계정 소유 확인과 운영자 감사 기록을 사용한다. 공개 소스/정적 웹앱의 클라이언트만으로 유료 기능을 완벽히 보호할 수 있다고 약속하지 않는다.
5. **오프라인 관측을 유지한다.** 마지막 검증 권한을 기기에서 확인할 수 있도록 캐시하고, 산에서 통신이 끊겼다고 갑자기 사용 중인 기능을 닫지 않는다. 서버가 서명한 권한과 갱신 정책, 환불/권한 철회의 온라인 반영 시점을 별도로 정한다. 영구 구매 이용권의 만료와 캐시 재검증 주기를 혼동하지 않는다.
6. **복원과 중복 결제를 처리한다.** 설정에 구매 복원을 제공한다. 같은 스토어 계정의 재설치와 Skylog 로그인 후 다른 플랫폼의 권한 조회를 구분한다. Apple 구매를 Google에 그대로 복원하는 API가 있는 것처럼 표현하지 않는다. 서로 다른 Skylog 계정으로 같은 거래를 중복 등록하지 않고, 계정 연결 오류는 지원 절차로 해결한다. 이미 해당 상품을 소유하면 새 구매를 권하지 않는다.
7. **기록은 결제와 독립적으로 보존한다.** 관측·사진·장비·학습 진도를 기존 Dexie DB에 그대로 둔다. 로그인이나 유료화 업데이트가 DB를 초기화하지 않도록 한다. 로그아웃·환불·무료 전환 후에도 본인 기록 열람·내보내기·삭제를 막지 않는다. 기기 간 **이용권 공유**와 **기록 자동 동기화**는 다른 기능이다. 초기 기록 이동은 기존 JSON 백업/가져오기를 유지한다.
8. **백업은 권한과 비밀값을 운반하지 않는다.** 현재 `src/db/exportImport.ts`가 일반 `settings`를 포함하므로 결제 토큰·로그인 토큰을 그곳에 그대로 넣지 않는다. 향후 전용 저장소/내보내기 제외 처리를 만들고, 예전 JSON 가져오기로 Pro 권한이 생기지 않는 회귀 검증을 추가한다. 구매 복원만으로 잃어버린 관측 기록이 복원된다고 안내하지 않는다.
9. **계정·결제가 생긴 만큼 문서를 갱신한다.** 현재 개인정보·스토어 문안의 “계정 없음/기기 내 보관” 범위를 새 구현에 맞게 바꾼다. 계정 삭제, 거래 기록 보유, 고객 지원, 환불 안내, 데이터 수집 신고를 실제 처리와 맞춘다. 거래 기록 삭제와 법정 보유 의무는 출시 사업자·지역을 확정한 뒤 확인한다.

## 5. 유료 출시 전에 해결할 실제 비용 의존성

현재 `src/services/weather.ts`는 무료 Open-Meteo API를 직접 사용한다. 공식 현재 정책상 무료 API는 **비상업용**이며, 상업용 사용에는 상업 라이선스와 고객용 API 구성이 필요하다. 데이터의 CC BY 4.0 출처 표기와 무료 API 서비스의 상업 이용 허용은 별개다. [Open-Meteo 가격 정책](https://open-meteo.com/en/pricing), [이용 약관](https://open-meteo.com/en/terms)

따라서 유료 판매 전에 ① 상업용 API 계약과 비용을 확정하고 비밀 키를 서버에 보관하는 프록시/캐시를 만들거나, ② 출시판의 날씨 기능을 제거하거나, ③ 상업 이용 가능한 다른 공급자로 바꾼다. 아직 계약·구매·공급자 변경을 실행하지 않았다. 구독 상품을 추가하지 않더라도 날씨를 제공하는 상업 앱에는 이 비용 검토가 필요하다. 기존 `docs/DATA-LICENSES.md`의 CC BY 표시만으로 이 검토가 끝난 상태로 취급하지 않는다.

## 6. 실제 결제 시작 전 결정과 검증

확정이 필요한 것은 **무료/꾸미기/클라우드 기능표, 최초 판매가, 출시 국가, 본인과 여자친구의 권한 연결 방법, 날씨 운영안**이다. 다음으로 실제 개발자 계정의 결제 계약·정산 정보·상품 ID와 운영 서버를 설정한다. 단순 결제 구현 작업과 계정 계약 동의·실제 판매 개시는 구분해 진행한다. 카드·비밀번호·서버 비밀 키를 저장소나 대화에 넣지 않는다.

진행 순서는 “기능/가격안 확정 → 결제·계정·이용권 구현 → 두 스토어 테스트 → 무료 코드와 복원 확인 → 스토어 상품/심사 → 실제 판매”다. 우선 현재 Android 개인 테스트와 iPhone 웹앱은 과금 없이 사용하며 UX를 검증한다.

- [ ] 무료 사용자, 일반 Pro 구매자, 본인 무료, 여자친구 무료를 각자 계정에서 확인
- [ ] Android·iPhone에서 구매/취소/대기/실패/승인·복원 확인
- [ ] 샌드박스 거래가 정식 서버 권한으로 섞이지 않음
- [ ] 앱 밖 무료 코드 사용 후 재실행해 권한 반영
- [ ] 재설치·다른 기기·같은 계정 로그인·다른 계정 전환 확인
- [ ] 구매 중 네트워크 단절 후 복구, 같은 거래 중복 처리, 환불/철회 확인
- [ ] PWA↔네이티브 이용권 연결과 중복 구매 방지 확인
- [ ] 오프라인 상태에서 이미 획득한 권한과 로컬 기록 사용 확인
- [ ] 유료화 업데이트·로그아웃·JSON 가져오기 후 관측/사진/진도 보존 확인
- [ ] 두 사람 무료 권한에는 자동 갱신 청구나 체험 종료 결제가 없음
- [ ] 상품 가격·세금/정산·약관·지원·개인정보·날씨 상업 이용 조건 확인

**이번 결과: 유료화·무료 제공 방안과 구현 설계 문서 완료. 결제·로그인·서버·상품 등록·두 사람의 정식 무료 이용권 발급·스토어 판매는 아직 구현/실행하지 않았다.**
