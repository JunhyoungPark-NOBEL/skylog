# Skylog 무료 범위와 선택형 꾸미기 판매 제안

> 최신 검토: **2026-09-09**. 기준 소스 `f5cf178`(beta.7/build12). 새 요청에 따라 유료화를 다시 검토하되 D-048의 기존 무료 범위를 유지한다. **이번 아바타·마당 개선도 무료로 제공하며, 이 문서는 향후 상품의 제안이다. 결제·상품 등록·무료 이용권 발급은 실행하지 않았다.**

현재 구현과 개통 대기는 [무료 서비스 구현](FREE-COMMUNITY.md), 공식 정책과 판단 근거는 [2026-09-09 조사](../plan/research/2026-09-09-monetization.md)에 있다. [꾸미기 확장안](COMMUNITY-AND-CUSTOMIZATION.md)과 [2026-09-08 조사](../plan/research/2026-09-08-community-monetization.md)는 이전 제안 이력이다.

## 추천: 무료 앱에 새 테마 팩 하나부터

**기본 이용은 무료, 별도로 제작한 꾸미기 팩은 1회 구매**를 추천한다. 월 구독은 지금 도입하지 않는다. 성취로 얻은 장식을 유지하면서 새 의상·마당 분위기를 선택하는 방식이 현재 앱에 맞는다는 제품 판단이다. 구매 의향이나 수익성을 검증한 결과는 아니다.

| 범위                                                             | 제공 방식                                | 현재와의 관계                                                                      |
| ---------------------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------- |
| 하늘·날씨·검색·달력·관측 안내·장비·코스·학습                     | 무료 유지                                | 정확도·기존 기능의 접근성을 결제로 나누지 않음                                     |
| 내 기록·사진·진도 열람, 로컬 백업/가져오기, 기본 마당·아바타     | 무료 유지                                | 이번 꾸미기 개선도 포함                                                            |
| 업적 장식, 사진 커뮤니티·댓글·신고·차단, 현재 개인 클라우드 백업 | 무료 유지                                | 기존 보상과 제공 한도를 소급 판매하지 않음                                         |
| 향후 별도 제작할 테마 팩                                         | **1회 구매 상품 1종부터 검토**           | 예: 새 의상·정원 배경·장식이 어울리는 ‘달빛 정원’ 팩. 기존 무료 아이템과 다른 상품 |
| 향후 추가 원본 보관·자동 동기화·장기 버전 보관                   | 실제 서비스와 비용 확인 후 구독 1종 검토 | 현재 수동 백업을 유료화하는 안이 아님. 가격·용량 미정                              |

처음에는 여러 Pro 등급·유료 재화·시즌 패스를 겹치지 않는다. 업적 전용 아이템은 계속 성취로 얻으며 구매로 같은 보상을 대신 얻거나 점수·정답·순위를 높이지 않는다. 유료 팩은 포함 항목이 정해진 상품으로 만들고 무작위 뽑기·사용 기한을 두지 않는다. 한 팩을 샀다고 모든 미래 상품이 포함된다고 안내하지도 않는다.

판매 준비가 되면 ‘내 마당 → 테마 미리보기’에서 적용 모습·포함 항목·1회 구매·복원 방법·현재 계정을 보여준 뒤 스토어 구매 화면으로 연결한다. 이미 가진 팩에는 보유 상태를 표시하고, 관측·퀴즈·백업 중 결제 화면을 끼우지 않는다. 이번 버전에 작동하지 않는 구매 버튼이나 가짜 가격은 넣지 않는다.

### 가격과 구독 판단

첫 팩의 **검토용 가격은 3,900원 1회**를 출발점으로 제안한다. 확정 판매가·시장 평균·경쟁사 가격이 아니다. 실제 팩의 품질과 제작비, 스토어 지원 가격·세금·지역 가격을 확인해 정한다. 기존 9,900원 Pro와 여러 월/연 요금 후보는 현행 상품이 아니다. 경쟁사의 현재 지역별 판매 가격은 이번에 확인하지 않았으므로 가격 근거로 쓰지 않는다.

무료 꾸미기 경험과 판매할 팩을 먼저 완성하고, 동의한 소수 이용자에게 만족도·미리보기 후 구매 의향을 확인한다. 불필요한 추적 SDK나 광고를 붙이지 않는다. 손익은 `판매 건수 × 실제 건당 정산액 − 제작비 − 추가 운영비`로 계산하며 수수료·세금·환불은 실제 계약대로 반영한다. 서버 저장/전송·메일·날씨 API·검토/고객 지원과 무료 사용자 비용도 포함한다. 1회 매출로 매월 운영비가 충당된다고 가정하지 않는다.

구독은 무료 수동 백업에 없는 원본 추가 저장·자동 동기화가 실제로 작동하고 비용을 측정한 뒤 검토한다. 지금은 월/연 가격을 정하지 않는다. 종료 시 로컬 기록과 1회 구매 팩은 보존하며, 클라우드 초과분은 사전 안내·유예·내보내기를 거쳐 처리하도록 약관을 설계한다. 무제한 저장을 약속하지 않는다.

## 구현된 것과 아직 없는 것

**현재 계정·서버는 실제 구현돼 있다.** beta.7에는 Supabase 인증, 접근 제어, 사진·댓글·운영 기능과 개인 백업이 있다. 일반 가입용 메일·실제 운영자 계정·실기기 확인은 남았다. 현재 개인 백업은 최대 5개, 각 20MB의 수동 스냅샷이며 자동 동기화가 아니다. [현재 범위와 제약](FREE-COMMUNITY.md)

로컬 꾸미기는 `src/personal/catalog.ts`와 `store.ts`, `progress`의 `personal.profile`/`personal.reward:<item>`을 사용한다. 한번 받은 장식은 관측 기록을 나중에 지워도 유지되고 기존 JSON 백업에 포함된다. 이를 무료 성취의 기록으로 유지하며 결제 증명으로 바꾸지 않는다.

현재 없는 것은 StoreKit/Play Billing 연결, 판매 상품, 거래 검증, 구매 복원, 플랫폼 간 유료 이용권, 무료 이용권 관리다. 기존 서버에 별도로 추가해야 하며 이 문서만으로 유료 출시 준비가 끝났다고 표시하지 않는다.

## Android·iPhone·PWA 구매와 복원

| 경로           | 첫 판매 시 추천                                       | 복원과 공유                                                               |
| -------------- | ----------------------------------------------------- | ------------------------------------------------------------------------- |
| Google Play 앱 | Play Billing 비소모성 1회 구매                        | 구매 조회·서버 검증 후 같은 Skylog 계정의 권한 확인                       |
| App Store 앱   | StoreKit 비소모성 IAP                                 | 현재 이용권 확인과 사용자가 누르는 구매 복원 제공                         |
| 독립 웹/PWA    | 처음에는 같은 계정의 보유 팩 이용부터. 웹 결제는 후속 | 서버 계정 권한 조회. Apple 거래가 Google 구매 내역으로 이전되는 것은 아님 |

Apple은 앱 내 디지털 기능 판매의 기본 경로로 IAP를 정하고, 다른 플랫폼에서 얻은 콘텐츠를 제공할 때 iOS에도 해당 상품을 IAP로 제공하도록 규정한다. Google도 아바타·추가 아이템·클라우드 서비스의 앱 내 판매를 Play Billing 대상으로 명시한다. [Apple 3.1.1·3.1.3(b)](https://developer.apple.com/app-store/review/guidelines/), [Google 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)

국가·스토어별 외부 결제/링크 예외는 자격과 조건이 다르다. 초기에는 표준 스토어 결제를 사용하고 전 세계 공통 외부 결제 버튼을 넣지 않는 안을 추천한다. 독립 PWA의 웹 결제와 네이티브 앱 안의 외부 결제 링크는 구분한다. Google의 ‘다른 곳에서 구매한 콘텐츠만 이용하는 앱’도 앱 안에서 판매하는 구성과 혼동하지 않는다. [Google 정책 설명](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en)

팩은 사용해도 소진되지 않는 상품으로 만든다. Apple의 비소모성 정의가 이에 해당한다. Android도 검증 후 승인(acknowledge)하며 소비(consume)하지 않는다. [Apple 상품 유형](https://developer.apple.com/help/app-store-connect/reference/in-app-purchases-and-subscriptions/in-app-purchase-types), [Google 구매 처리](https://developer.android.com/google/play/billing/integrate?hl=en)

## 본인과 여자친구는 각자 계정으로 무료

현재는 모두 무료이므로 특수 권한이 필요하지 않다. 향후 판매 도입 시 **각자의 검증된 Skylog 계정에 서버가 무료 이용권을 부여**하고 Android·iPhone·PWA에서 같은 계정으로 확인하도록 설계한다. 비밀번호나 Apple/Google 계정은 공유하지 않는다.

본인 `owner`, 여자친구 `complimentary`는 무료 제공의 출처로 기록하며 커뮤니티 운영자·DB 관리자 역할과 분리한다. 팩의 무료 권한은 만료 없이 제공하고 자동 결제·체험 종료일을 두지 않는다. 새 유료 상품도 두 사람의 무료 목록에 추가하도록 운영한다. 미래 클라우드 비용은 운영자가 부담하되 저장·스팸 방지 등 서비스 한도는 별도로 정한다.

정식 스토어 무료 지급에는 Apple의 무료 offer code와 Google의 한 번 구매 상품 promo code를 우선 활용해 실제 무료 거래를 계정에 연결한다. Apple은 배포 가능 앱·승인된 IAP, Google은 활성 상품/구매 옵션 등의 조건이 있다. 코드가 다른 스토어나 PWA 권한으로 자동 변환되지는 않는다. [Apple offer code](https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/create-offer-codes-for-in-app-purchases), [Google promo code](https://support.google.com/googleplay/android-developer/answer/6321495?hl=en)

별도 무상 서버 권한도 심사 설명에 공개한다. **서버 grant가 IAP 규칙의 자동 예외라고 단정하지 않는다.** 공식 무료 거래와 무상 제공 범위를 구분하고, 숨은 버튼·라이선스 키·공용 비밀번호로 판매 규칙을 우회하지 않는다. Google 구독 프로모션은 무료 체험 기간이므로 두 사람의 영구 무료 이용권 대용으로 쓰지 않는다. [Apple 심사 지침](https://developer.apple.com/app-store/review/guidelines/), [Google 프로모션 범위](https://support.google.com/googleplay/android-developer/answer/6321495?hl=en)

## 이용권 설계와 기록 보존

다음은 **미구현 설계**다. 기존 Supabase 로그인을 재사용하되 유료 권한을 로컬 업적 보상과 분리한다.

1. **거래와 권한 분리:** 상품 대응표·검증 거래·상품별 이용권·무료 부여 감사 이력을 서버에 둔다. 검증된 사용자 UUID, 상품, 출처, 상태, 만료일, 갱신 시각을 기록한다. 두 사람의 실제 UUID와 상품 ID는 아직 정하지 않았다. 테스트와 정식 거래 환경을 구분한다.
2. **서버만 권한 변경:** 사용자는 자신의 이용권만 읽고 부여·철회·거래 연결은 검증된 서버 경로에서 처리한다. 담당자·대상·상품·사유·시각을 남기고 결제 관리와 커뮤니티 운영 역할을 분리한다. 이메일 문자열, 프로필, 로컬 `isPro`, 백업 JSON을 믿고 해금하지 않는다.
3. **완료된 거래 검증:** 스토어 거래 서명/구매 토큰·앱·상품·환경·완료 상태와 환불/철회를 확인한다. 대기 결제는 해금하지 않는다. 같은 거래를 여러 계정에 중복 등록하지 않고 알림 재전송에도 한 번만 처리한다. 비소모성 구매를 소비하지 않는다. [Google 구매 보안](https://developer.android.com/google/play/billing/security), [구매 처리](https://developer.android.com/google/play/billing/integrate?hl=en)
4. **계정 연결 확인:** 구매 전 현재 Skylog 계정을 보여준다. Apple `appAccountToken`과 Google 난독화 계정 식별자를 활용하되 식별자만으로 거래를 신뢰하지 않는다. 잘못된 연결은 지원 절차에서 확인하고 로그인 계정 변경만으로 거래 소유자를 자동 변경하지 않는다. [Apple 계정 연결](https://developer.apple.com/documentation/appstoreserverapi/appaccounttoken), [Google 계정 검증](https://developer.android.com/google/play/billing/security)
5. **복원·오프라인 지원:** iOS 현재 이용권 확인과 명시적 구매 복원, Android 재개 시 구매 조회를 구현한다. 권한 캐시는 계정별로 분리하고 계정 전환 시 이전 캐시를 사용하지 않는다. 온라인 조회 실패를 권한 철회로 취급하지 않으며 오프라인 재검증 유예와 실제 환불 반영 정책을 정한다. [Apple 복원](https://developer.apple.com/documentation/storekit/appstore/sync%28%29?changes=_6), [Google 구매 조회](https://developer.android.com/google/play/billing/integrate?hl=en)
6. **기존 데이터 보존:** 로그인·결제·로그아웃·환불이 Dexie 관측/장비/사진/진도·무료 보상을 지우거나 열람·백업·삭제를 막지 않는다. 이용권 공유와 기록 자동 동기화는 별개이며 수동 JSON/클라우드 복원은 유지한다. 결제 토큰·서버 비밀값은 백업에서 제외하고 가져온 파일로 유료 팩이 생기지 않게 검사한다. 로그인 토큰은 이미 Supabase 전용 저장 키로 분리돼 있다.

공개 코드·그림을 클라이언트 검사만으로 완벽히 보호할 수 있다고 약속하지 않는다. 서버는 정식 권한과 온라인 서비스 접근을 검증하며 로컬 기록을 유료 권한에 종속시키지 않는다. 계정 삭제·거래 보유·환불·구독 종료·지원을 실제 구현에 맞춰 개인정보 문서와 스토어 신고에 반영한다.

## 유료화 전 날씨 운영안

현재 `src/services/weather.ts`는 `api.open-meteo.com/v1/forecast`의 무료 API를 직접 쓴다. **무료 API는 비상업용**이며 고객 API 플랜에는 상업 이용 라이선스가 포함된다. CC BY 4.0 데이터 출처 표기는 API 서비스 계약을 대신하지 않는다. [Open-Meteo 서비스 구분](https://open-meteo.com/en/pricing), [이용 약관](https://open-meteo.com/en/terms)

날씨는 무료여도 앱에서 꾸미기를 판매하면 상업 이용 조건을 검토해야 한다는 것이 이 조건을 적용한 판단이다. 이번 무료 업데이트에서는 계약을 바꾸지 않지만 판매 전 상업 라이선스·고객 API를 준비하거나 상업 이용 가능한 대체 공급자를 검토한다. 기존 날씨를 갑자기 없애는 안은 추천하지 않는다. 비밀 키는 앱/PWA의 `VITE_` 변수 대신 서버 프록시·캐시에서 관리한다.

현 코드는 시간별 변수 10개·기본 2일을 요청한다. Open-Meteo는 변수가 10개를 초과하거나 요청 기간이 길어지면 호출 산정이 달라질 수 있다고 안내하므로, 향후 기능 추가 때 HTTP 요청 수만으로 비용을 계산하지 않는다. 실제 요청 조합·캐시·사용량으로 견적을 내고 날씨·메일·저장/전송·지원비를 포함해 지속 가능성을 확인한다. 계약·유료 플랜 구매는 아직 하지 않았다. [호출 산정 안내](https://open-meteo.com/en/pricing)

## 실제 판매 전 확인

무료 꾸미기 개선과 데이터 보존을 먼저 검증·배포한다. 이후 판매 팩을 완성하고 상품 범위·가격·출시 국가·날씨 운영안·정산 주체를 정한다. 결제 연동과 테스트를 마친 뒤 스토어 상품 심사를 거쳐 판매한다. 이 문서의 후보 가격을 앱에서 청구하지 않는다.

- [ ] 무료 사용자와 두 사람 모두 기존 기능·획득 장식·백업 유지
- [ ] 실제 판매 팩의 품질·저작권·오프라인/야간/성능·미리보기 확인
- [ ] 정상·취소·대기·중단·환불·중복 알림·구매 복원을 각 스토어에서 검증
- [ ] 무료 코드·두 사람 권한·계정 전환·재설치·PWA 연결 확인
- [ ] 백업 가져오기로 결제 권한이 생기지 않고 기록·무료 보상은 유지
- [ ] 일반 가입 메일·운영 담당자·날씨 상업 이용·정산 계약·지원·개인정보 준비

**이번 결과는 무료 범위를 보존하는 판매안과 근거 문서다. 결제·유료 이용권·자동 동기화는 미구현이며 실제 상품·판매가·무료 이용권은 등록하거나 발급하지 않았다.**
