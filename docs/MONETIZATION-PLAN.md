## ‘난이도 2·3’을 적용할 정확한 위치

기준은 문항의 `QuizItem.difficulty: 1 | 2 | 3`이다. 현재 Journey의 하늘 28스테이지와 관측 12스테이지는 각 트랙의 1/2/3장이 각각 난이도 1/2/3에 대응한다. 직접 대조한 결과 **현재 스테이지 내부 혼합은 없다.** 난이도 1은 합계 15스테이지, 난이도 2·3은 25스테이지다. 다만 문항 유형에는 장과 별도의 난이도가 있으므로 향후 팩 변경 뒤에도 장 번호만으로 판매 범위를 추측하지 않는다.

실제 혼합 경로는 `selectQuiz()`의 자유 연습·복습·천체별 출제와 미션의 `quizIds`다. 향후에는 이 경로와 스테이지 시작/다음 단계/답안 저장에 같은 접근 판정을 적용해야 한다. 화면의 어려운 장 버튼만 잠그면 직접 링크나 미션·복습에서 다른 결과가 된다. 기술상 비활성인 `enabled: false`와 결제 권한은 별개로 두어 기존 응답·배지 집계를 망가뜨리지 않는다.

판매 도입 이후 무료 사용자의 새 연습·새 복습은 난이도 1에서 출제하고, 난이도 2·3의 새 풀이/재도전에는 이용권을 확인하는 안이다. 이미 저장한 답안·점수·완료 이력과 제공 가능한 이전 해설 열람은 계속 무료로 둔다. 풀이 가능한 문항이 없을 때는 데이터 오류 대신 무료 학습으로 이동할 수 있게 안내한다. 결제했다고 선행 단계 80% 통과 조건을 건너뛰거나 점수·도장을 자동 부여하지 않는다.

### 무료 코스의 혼합 문항을 먼저 해결해야 한다

맨눈·쌍안경 20미션 중 **15미션이 난이도 2·3의 서로 다른 20문항**을 참조한다. 현재 상태에 전역 난이도 잠금을 붙이면 무료 코스 완료가 막힌다. 무료 미션의 해당 확인문항은 목적에 맞는 난이도 1 문항으로 새로 작성/교체하고, 어려운 원문항은 심화 퀴즈에 남기는 안을 추천한다. 답안 몇 개를 조용히 건너뛰고 미션을 완료 처리하지 않는다.

이 조정은 미래 구현 작업이다. 원문항의 난이도 숫자만 내려 분류를 왜곡하지 않으며 새 문항 ID·내용/보기 버전을 관리한다. `missionKey()`는 단계 내용의 해시를 쓰므로 미션을 바꾸면 과거 시작·체크 이력이 그대로 연결되지 않는다. 이전 버전 완료 표시와 새 버전 학습을 분리해 보존하는 이관 설계를 먼저 만들고, 과거 응답을 새 문항 정답으로 자동 변환하지 않는다. 이번에는 팩·코드·DB를 변경하지 않는다.

## ‘망원경 코스’와 실제 관측 도구를 구분

유료 후보는 `courseTheme=telescope`로 탐색하는 **학습 콘텐츠**다. `telescope-first-record`, `telescope-honest-view`의 총 10미션과 `group=starhop`의 6개 안내 코스를 포함하는 범위로 제안한다. 스타호핑의 `level: 1 | 2 | 3`은 코스 안내 수준이며 퀴즈의 `difficulty`가 아니다. 망원경 묶음에 포함되는 6코스 전체를 기준으로 삼는다.

`#/equipment`의 숫자 편집·시야 계산과 `#/telescope`의 기본 목표 찾기·정렬·FOV·일반 별길 사용은 무료 관측 도구로 유지한다. 같은 화면에서 유료 코스의 설명·고정 경로·완주 진도를 불러오는 `course=<id>` 사용과 구분해야 한다. 코스를 유료로 만들겠다는 요청을 망원경 관련 앱 기능 전체 유료화로 넓히지 않는다.

향후 권한은 주소의 `theme` 값이 아니라 실제 경로/미션/코스 ID와 상품 대응표로 확인한다. 현재 `CoursesScreen`은 직접 `mission`/`hopCourse`가 있으면 상위 주제 선택 없이 상세를 열 수 있다. 상위 카드 하나에만 잠금을 붙이지 않고 직접 링크·재실행·코스 시작도 같은 정책을 적용하는 것이 후속 구현 조건이다.

## 기존 진도·보상과 무료 이용 보존

현재 앱에서는 모든 학습에 계속 접근할 수 있다. 판매 시행일을 정하게 되면 변경 범위를 미리 안내하고, 진행 중인 풀이를 중간에 끊거나 마지막 답안 저장을 막지 않는 전환 절차를 마련한다. 이전 베타 사용 이력만으로 정식 구매가 생겼다고 처리하지 않는다. 기존 이용자에게 추가로 줄 학습 이용권이나 유예는 실제 시행 전에 별도 정책으로 정하며 이번에 발급하지 않는다.

- `learn.attempt:*`, `learn.sr:*`, `learn.stage:*`, `learn.stage-draft:*`, 미션 시작/체크·스킬 이벤트는 보존한다. 판매 접근 판정이 전체 학습 스냅샷에서 이전 기록을 제거해서는 안 된다.
- 단계 ID·문항 버전과 최고점·완료 결과를 유지한다. 내용이 바뀌면 이전 버전을 읽을 수 있게 하고 새 버전 재도전과 구분한다. 구매 복원은 구매한 학습 권한을 복구하며 잃어버린 관측 기록을 되살리는 기능이 아니다.
- `personal.reward:*`와 아바타 보상·코디·마당 배치는 그대로 보존한다. 구매 취소·환불·로그아웃으로 이미 받은 장식을 빼앗거나 기존 기록 백업을 막지 않는다. 신규 구매도 실제 학습 성취를 대신하지 않는다.
- 업적 화면과 보상 지급 자체는 무료다. 현재 기본 장식과 아바타 보상은 무료 관측·이야기·5스테이지 등의 경로로 계속 얻도록 검증한다. 다만 100문항 숙련·20/40스테이지·24/30미션·스타호핑 코스 완주 도전은 향후 유료 학습 범위와 연결될 수 있으므로 그 조건을 명확히 표시한다. ‘모든 도전을 무료로 완주할 수 있다’고 안내하지 않는다.
- 사진 이미지·댓글·반응·신고·차단과 현재 백업의 무료 범위를 유지한다. 무료는 무제한 서버 저장을 뜻하지 않으며 현재 업로드/발송/저장 한도는 그대로 구분해 안내한다.

## 본인·여자친구 무료 이용과 복원

두 사람은 향후 심화 퀴즈·망원경 코스도 무료로 쓰도록 계획한다. 각자의 검증된 Skylog 계정 UUID에 **만료 없는 심화 학습 권한**을 서버에서 부여하고 Android·iPhone·PWA에서 같은 계정으로 확인한다. `owner`/`complimentary`는 무료 제공 사유이며 커뮤니티 운영자나 DB 관리자 역할이 아니다. 비밀번호·스토어 계정 공유와 클라이언트 이메일 특례를 사용하지 않는다.

유료 거래·무료 grant·상품별 권한을 분리하고 서버만 부여/철회하게 한다. 실제 사용자 UUID·스토어 상품 ID·부여 감사 이력은 후속 설정이며 이번에 생성하지 않았다. 로컬 `isPro`, 숨은 버튼, 가져온 JSON의 권한 플래그는 유료 접근 증명으로 인정하지 않는다. 본인/GF 권한에는 무료 체험 종료나 자동 청구가 없다.

정식 스토어 무료 지급에는 Apple offer code·Google 비소모성 상품 promo code를 우선 검토해 정상 거래를 계정에 연결한다. 별도 무상 grant도 심사 설명에 공개하며 서버 기능만으로 IAP 규칙의 자동 예외가 된다고 단정하지 않는다. 코드 자체가 다른 플랫폼 권한으로 자동 이전되는 것은 아니다. [Apple 무료 코드](https://developer.apple.com/help/app-store-connect/manage-in-app-purchases/create-offer-codes-for-in-app-purchases), [Google 프로모션](https://support.google.com/googleplay/android-developer/answer/6321495?hl=en)

구매 전 연결 계정을 보여주고, 검증된 거래를 한 계정에만 연결한다. 같은 스토어의 재설치 복원과 Skylog 로그인으로 다른 플랫폼에서 권한을 조회하는 흐름을 구분한다. iOS의 현재 이용권·명시적 복원과 Android 구매 조회를 지원하고 중복 구매를 방지한다. 권한 캐시는 계정별로 분리하며 통신 실패와 실제 환불/철회를 구분한다. 오프라인 관측·기록은 계속 사용할 수 있게 한다. [Apple 복원](https://developer.apple.com/documentation/storekit/appstore/sync%28%29?changes=_6), [Google 구매 검증](https://developer.android.com/google/play/billing/security)

## 결제 경로·가격·운영비

첫 상품은 소진되지 않는 심화 학습 이용권으로 설계한다. App Store에서는 비소모성 IAP, Play에서는 비소모성 1회 구매를 기본으로 삼는다. Google은 검증된 완료 구매를 승인(acknowledge)하고 소비하지 않는다. 대기·취소·환불·중복 알림·테스트/정식 환경을 구분한다. 독립 PWA의 웹 결제는 별도 후속으로 두고 먼저 같은 계정의 권한 이용을 지원하는 안이다. [Apple IAP 유형](https://developer.apple.com/help/app-store-connect/reference/in-app-purchases-and-subscriptions/in-app-purchase-types), [Google 구매 처리](https://developer.android.com/google/play/billing/integrate?hl=en)

앱 내 학습 콘텐츠 판매는 디지털 구매이므로 스토어 결제 정책을 따른다. 다른 플랫폼에서 얻은 콘텐츠를 iOS에서 제공할 때 동일 상품의 IAP 제공 조건, 국가별 외부 결제/링크 예외를 실제 출시 때 확인한다. 처음부터 공통 외부 결제 버튼이나 자체 라이선스 키로 대체하지 않는다. [Apple 3.1.1·3.1.3(b)](https://developer.apple.com/app-store/review/guidelines/), [Google 결제 정책](https://support.google.com/googleplay/android-developer/answer/9858738?hl=en)

**가격은 미정이다.** 이전 외형 팩 3,900원이나 Pro 9,900원을 이 상품 가격으로 자동 적용하지 않는다. 학습 구성과 미리보기, 콘텐츠 제작·지원비, 스토어 실제 정산액·환불·세금, 메일·저장/전송·날씨 비용을 확인해 정한다. 현재 원본 추가 저장·자동 동기화가 없으므로 구독이나 무제한 클라우드를 묶지 않는다.

현재 날씨는 무료 Open-Meteo API를 직접 사용한다. 학습 상품을 판매해 앱을 상업화할 때도 날씨 API의 비상업/상업 조건은 검토해야 한다. 판매 전에 고객 API 라이선스 또는 적합한 공급자를 정하고 비밀 키는 서버에서 관리한다. CC BY 출처 표기와 API 서비스 계약은 별개다. 이번에 계약이나 유료 API 구매를 실행하지 않았다. [Open-Meteo 조건](https://open-meteo.com/en/terms), [서비스 구분](https://open-meteo.com/en/pricing)

## 실제 판매 전에 완료할 작업

1. 무료 난이도 1·맨눈/쌍안경 미션과 유료 난이도 2·3·망원경 콘텐츠의 ID/버전 대응표를 확정한다. 비활성 `skyPick`은 제외한다.
2. 혼합 문항을 쓰는 무료 15미션을 무료로 완료할 수 있게 정리하고 이전 미션/스테이지·보상 이력을 보존한다.
3. 검증된 계정별 이용권·구매 복원·오프라인/계정 전환·본인/GF 무료 grant를 구현한다. 현재 제품의 무료 동작과 구분해 실제로 검증한다.
4. 모든 퀴즈 진입점·직접 링크·코스 연결·다음 단계에서 같은 정책을 확인하고, 무료 코스에 숨은 추가 결제가 없는지 검사한다.
5. 가격·시행일·기존 이용자 전환·상품 포함 범위·날씨 운영안·정산·고객 지원·스토어 심사를 마친 뒤 판매한다.
