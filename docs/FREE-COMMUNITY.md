# 무료 꾸미기와 사진 커뮤니티 — beta.7

## 제공 범위

2026-09-08 사용자 결정에 따라 전부 무료다. D-046 및 기존 유료화 제안은 현재 구현 기준이 아니다. 결제, 구독, 광고, 유료 우회 경로가 없다. 기존 다섯 하단 탭과 관측·센서·퀴즈·기록 형식을 유지한다.

- 배우기 오른쪽 사람 아이콘 또는 설정 → **내 마당**. 네 가지 기본 장식, 기존 업적으로 얻는 여덟 장식, 다섯 배치 자리, 옷 네 색·피부 세 톤·모자 세 종류를 제공한다. 소유한 장식과 잠긴 보상은 다른 화면으로 나눈다.
- 내 마당 / 천체 상세 → **모두의 사진**. 전체/내 사진과 대상 필터, 사진 상세, 장비·사진 유형, 축하 반응, 댓글을 제공한다. 이미지 중심 목록에 관리 도구를 쌓지 않는다.
- 계정은 공유·댓글·개인 클라우드 백업을 쓸 때만 필요하다. 원래 기록을 저장하는 것만으로 사진이 공개되지 않는다. 수정하면 다시 검토를 받으며 작성자는 나만 보기로 전환하거나 삭제할 수 있다.
- 운영자 화면: 사진/댓글/신고/재검토 큐, 승인·반려·숨김·복구·계정 제한·처리 사유. 작성자는 계정에서 검토 내역을 확인한다. 일반 계정이 운영자 플래그를 자칭할 수 없다.

## 현재 연결 상태

- Supabase 무료 조직 `skylog`, 프로젝트 `ijxuwtbcwifttiuwvqrh`, 서울 `ap-northeast-2`. 사용자가 직접 가입·프로젝트 비밀번호 설정을 마쳤다.
- 테이블·RLS·비공개 버킷·서버 함수를 실제 배포하고 임시 계정 세 개로 검사했다. 검사 계정과 파일은 종료 시 삭제했다. 샘플 사진이나 가짜 회원을 공개 데이터에 심지 않는다.
- **일반 가입은 아직 개통 전이다.** Supabase 무료 기본 메일은 조직 구성원 주소에만 보낼 수 있고, 기본 발송으로는 메일 템플릿 변경도 거부된다. 별도 SMTP 설정을 기다리고 있다. 일반 회원이 사용할 수 있다고 안내하지 않는다.
- 기본 메일 링크는 요청한 브라우저에서 PKCE로 처리한다. 서버 사이트 URL은 실제 Pages URL로 설정했다. 커스텀 SMTP 연결 뒤 `supabase/templates/otp.html`을 적용하면 Android에서도 이메일 인증번호를 앱에 직접 입력할 수 있다.
- 실제 운영자 앱 계정 지정·일반 외부 주소로 메일 수신·실기기 공유/복원을 완료하기 전 T9 완료 태그를 만들지 않는다.

## 데이터와 권한

로컬 `progress`의 `personal.profile`과 `personal.reward:<item>`을 사용한다. 보상은 하나의 Dexie 트랜잭션에서 고유 키로 기록하며 다시 가져와도 중복되지 않는다. 기존 업적 판정은 바꾸지 않는다. 한번 받은 꾸미기 보상은 관측 기록을 나중에 지워도 유지한다. 이 로컬 성취를 온라인 경쟁 점수로 사용하지 않는다. 기존 JSON 백업에 배치와 보상이 포함되며 잘못된 색·아이템·중복 배치는 읽을 때 정규화한다.

온라인 테이블은 `sky_members/posts/comments/blocks/reactions/reports/appeals/audit/backups/objects/usage/moderators`다. RLS를 모두 켜고 일반 계정에는 직접 쓰기를 주지 않는다. 공개된 내용·작성자 자신의 내용·실제 운영 역할별로 읽기를 제한하며, 운영자도 나만 보기 사진을 공개로 바꾸는 RPC를 실행할 수 없다. 데이터베이스 관리자 권한은 별도 운영 권한이다.

인증 토큰은 Supabase 전용 저장 키를 쓰며 Dexie 백업에서 제외한다. 계정이 바뀌면 계정별 화면을 새로 만들어 이전 계정의 목록·복원 미리보기를 재사용하지 않는다. 백업은 현재 계정으로 보내기 전 위치·사진 포함을 명확히 알린다. 복원은 기존 검증기와 `newest` 가져오기를 사용하고, 자동 양방향 동기화라고 표현하지 않는다. 최대 5개/각20MB다.

공유 사진은 클라이언트1600px 축소 후 서버에서 JPEG를 다시 디코딩·인코딩한다. 서버는 최대4MP/96MB 디코더 제한과 입력 크기 제한을 적용한다. EXIF/GPS/주석을 복사하지 않으며 원본을 공개 저장하지 않는다. private 버킷에만 넣고 사진 접근 시 RLS를 검사한 뒤60초 URL을 발급한다. 이미 다운로드한 사본을 회수할 수 있다고 약속하지 않는다. 사진 속 얼굴/주소나 설명의 개인정보는 게시자 확인과 운영자 검토가 필요하다.

하루 사진10장/댓글40개, 댓글 간20초, 신고10개/재검토5개 제한은 서버가 적용한다. 사진을 지워도 업로드 횟수는 되돌아가지 않는다. 사용자별 잠금으로 병렬 요청을 직렬화한다. 모든 신규·수정 글은 검토 후 공개하며, 신고 수만으로 자동 제재하지 않는다. 계정 삭제는 최근 로그인15분 이내에만 실행하고 개인 파일부터 제거한다.

## 서버를 이어서 운영하는 법

1. Supabase Authentication → Email에서 사용할 SMTP를 연결한다. **서비스 키·SMTP 비밀번호를 앱/VITE 변수나 Git에 넣지 않는다.**
2. `supabase/config.toml`의 메일 템플릿은 SMTP 설정 후 적용한다. 지금 기본 메일 상태에서 전체 `config push`를 하면 템플릿 변경이400으로 거부된다. 이미 적용된 사이트 URL·메일 확인·MFA 설정을 임의로 완화하지 않는다.
3. 사용자가 앱 계정을 만들고 이메일 인증을 마친 뒤, 해당 사용자 UUID를 확인하여 SQL 관리자로 `insert into public.sky_moderators(id) values ('검증한-사용자-UUID');`를 실행한다. 첫 가입자를 자동 운영자로 만들지 않는다.
4. 공개 전 담당자가 신규 글·신고·재검토를 매일 확인할 수 있는지 정한다. 초기 목표는 신고 접수 후48시간 이내 검토이며 실제 대응 담당자와 일정이 확정되기 전 이를 앱에서 보장하지 않는다.
5. 일반 외부 이메일로 로그인, 사진 등록→검토→공개→차단→삭제, 다른 기기의 개인 백업 복원을 확인한다.
6. 메일 템플릿 적용·외부 발송을 확인한 뒤 GitHub 변수 `VITE_COMMUNITY_EMAIL_CODE=true`, `VITE_COMMUNITY_SIGNUPS_READY=true`로 웹/모바일을 다시 빌드한다. false 기본값은 운영자 시험 안내를 표시한다.

배포 대상은 `supabase/migrations/` 순서와 `supabase/functions/community/`다. 초기 마이그레이션은 CLI Management API로 실제 적용했으며, 운영 중에는 같은 파일을 재실행하지 않는다. 관리형 배포에 옮길 때 기존 적용 이력을 먼저 등록한다. 로컬 검사는 `pnpm test:community-db`. 실제 서버 검사는 `SKYLOG_LIVE_TEST=yes`를 명시하고 `node tests/backend/live-community.mjs`로 실행한다. 이 명령은 CLI 인증을 사용하고 전용 임시 계정만 생성·정리한다. 개인 키는 출력하지 않는다.

## 검증과 남은 범위

기존501개에 꾸미기3개를 추가한 단위504개, 타입/lint 검사, 실제 PostgreSQL 권한27개, 실제 Supabase22개 검사를 통과했다. 360px/영어125%/야간 적색·키보드 배치·새로고침 보존·목록과 상세 분리를 Playwright로 검사한다. 화면에 보이는 달 예시는 테스트가 주입한 그림이며 공개 서버 콘텐츠가 아니다.

일반 이메일 발송, 운영자 실제 계정 지정, 실기기 사용, 스토어 개인정보 수집 신고·UGC 운영 준비가 남았다. 자동 동기화/공개 리더보드/DM/사진 원본 공유/하늘 위 장식 오버레이는 이번 버전에 없다. 앱 계정 삭제와 로컬 기록 삭제는 별개다. APK는 설치된 앱과 같은 개인 테스트 인증서가 필요하므로 이 PC에 없는 키를 새로 만들어 대체하지 않는다.
