# 댓글 기능 검토 — 2026-09-09

기준은 원격 main `9d39492`의 beta.8/build13이다. 기준 타입 검사와 단위 528개가 통과한 뒤 댓글 경로를 검토했다. 이 문서는 댓글 구현·자동 검사·실제 서비스 개통을 구분한다.

## 수정한 문제

- 사진 신고·재검토 사유와 댓글 초안이 같은 상태를 쓰던 문제를 수정했다. `CommentsPanel.tsx`가 사진 ID와 로그인 계정별로 독립된 초안을 관리한다.
- 댓글 전송 중 입력을 막아, 전송 응답이 도착할 때 뒤이어 쓴 초안이 지워지지 않게 했다. 전송 실패 시 원래 초안을 보존한다. RPC는 성공하고 목록 읽기만 실패한 경우에는 전송 완료와 새로고침 오류를 구분하며, 새로고침은 댓글을 다시 전송하지 않는다.
- 다른 사진이나 계정으로 전환하면 이전 조회를 취소하고 늦은 응답을 무시한다. 이전 계정의 차단 응답이 새 화면을 이동시키는 것도 막았다.
- 오래된 댓글 100개만 보이던 고정 조회를 최신 50개와 이전 페이지 조회로 바꿨다. `(created_at, id)` 커서로 같은 시각의 댓글도 빠짐없이 이어 읽고, 화면에는 읽은 범위를 시간순으로 표시한다. 작성자 이름은 해당 페이지 작성자만 조회한다.
- 댓글 새로고침을 추가했다. 운영 승인 등 다른 사람의 변경은 이 버튼이나 화면 재진입으로 확인한다. 실시간 자동 구독 기능으로 표현하지 않는다.
- 운영 검토 탭을 바꾸는 동안 이전 탭의 행과 승인 버튼을 숨긴다. 조회 오류 시 재시도할 수 있고, 계정을 바꾼 뒤 이전 비동기 사진 열기가 뒤늦게 화면을 이동시키지 않는다.

주요 구현: `src/features/community/CommentsPanel.tsx`, `src/community/comments.ts`, `CommunityScreen.tsx`의 댓글 통합부, `ModerationScreen.tsx`. 기존 사진 업로드·사진 가공 코드는 이 댓글 작업에서 바꾸지 않았다.

## 유지한 서버 규칙

| 단계                | 현재 동작                                                                                                                                       |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 댓글 작성           | 로그인하고 이용 규칙에 동의한 활성 계정이 공개 사진에 작성한다. 최초 상태는 `pending`이다.                                                      |
| 검토 대기·반려·숨김 | 해당 사진을 읽을 수 있는 댓글 작성자와 운영자만 본다. 일반 독자에게는 공개되지 않는다.                                                          |
| 운영 승인           | 운영자 RPC만 `published`로 바꿀 수 있고 이유와 감사 이력을 남긴다.                                                                              |
| 다른 사람의 댓글    | 공개 댓글만 조회하며, 작성자 이용 제한·양방향 차단·부모 사진의 공개 상태를 RLS가 적용한다.                                                      |
| 삭제                | 활성 계정이 자기 댓글을 `deleted`로 바꾼다. 화면 조회는 삭제 상태를 제외하고 운영자가 다시 승인하지 못한다. 서버의 소프트 삭제 정책은 유지했다. |
| 신고·재검토         | 대상 종류와 댓글 ID를 전달한다. 미해결 중복 신고·자기 댓글 신고·다른 사람의 재검토 요청은 제한한다.                                             |
| 이용 제한 계정      | 새 글뿐 아니라 자기 댓글 삭제도 현재 `ACCOUNT_UNAVAILABLE`로 제한한다. 이번 작업에서는 운영 정책을 바꾸지 않았다.                               |
| 속도 제한           | 계정별 20초 간격·하루 40개 제한을 유지하며 댓글을 삭제해도 제한이 초기화되지 않는다.                                                            |

서버 migration·Edge 함수 변경은 없다. 이번 수정 때문에 서버 DB 쓰기나 함수 재배포를 할 필요는 없다.

## 검사 결과

- **PostgreSQL/RLS 46개 통과**: 기존 27개에 익명 RPC 실행 거부, 직접 상태 변경·자기 승인 거부, 대기·반려·승인·삭제 상태의 관객 구분, 다른 작성자의 삭제 차단, 댓글 신고·중복 신고·재검토·삭제 후 재승인 거부·부모 사진 숨김·삭제 후 속도 제한 등을 추가했다. PGlite에 기존 migration을 실행한 결과다.
- **댓글 단위 13개 통과**: 실제 Supabase SDK가 만드는 필터·정렬·동일 시각/미세초 커서·취소 신호·읽기 오류 6개, React 입력·전송·읽기 실패·사진/계정 전환·신고 사유·이전 페이지 7개다.
- **타입 및 lint/포맷**: 통합 타입/lint·전체 단위541개와 이후 추가된 API6개, 총547개 고유 단위 검사 통과를 루트의 `qa-build14` 로그에서 확인했다. 변경 파일 포맷도 통과했다.
- **브라우저 회귀 6개 통과**: 루트가 `tests/e2e/comments.spec.ts` 전체 통과를 확인했다. 작성→대기→다른 작성자 비노출→운영 승인→비로그인 공개, 삭제/신고/차단, 121개 동시각 댓글 페이지, 로그아웃 중 느린 응답, 운영 검토 탭 전환을 포함한다. 가짜 세션과 라우트 모킹을 사용하고 실제 Supabase로 나가는 나머지 경로는 차단한다. 전체 브라우저75개도 통과했다. 네이티브 빌드와 배포 결과는 MOBILE-RELEASE.md에 별도로 기록한다.

전체 신규 단위는 `tests/unit/comments.test.ts`, `tests/unit/communityComments.test.tsx`; DB 검사는 `tests/backend/community.test.mjs`에 있다. 실제 서비스에 테스트 댓글이나 메시지를 보내지 않았고 테스트 계정을 생성하지 않았다.

## 실제 서비스 읽기 확인과 개통 상태

`.env.local`의 공개 URL·키를 메모리에서 읽어 GET 요청만 실행했다. 값과 행 본문은 출력하지 않았다.

| GET 점검                                           | 결과                                   |
| -------------------------------------------------- | -------------------------------------- |
| 공개 사진 SELECT                                   | HTTP 200, 0행                          |
| 공개 댓글 SELECT                                   | HTTP 200, 0행                          |
| `pending/rejected/hidden/deleted` 댓글 필터 SELECT | HTTP 200, 0행                          |
| 익명 `sky_action`의 GET 실행                       | HTTP 401, PostgreSQL `42501` 권한 거부 |

익명 POST 쓰기 시험을 한 것은 아니다. 익명 함수 실행 권한은 위 읽기 전용 요청과 로컬 PostgreSQL 권한 검사로 확인했다. 실제 데이터가 0개이므로 실제 서비스에서 작성자·운영자·다른 독자가 주고받는 전체 흐름을 확인했다는 뜻도 아니다.

`VITE_COMMUNITY_SIGNUPS_READY=false`, `VITE_COMMUNITY_EMAIL_CODE=false`를 그대로 유지했다. **일반 가입 메일과 실제 운영자 계정 개통이 완료되지 않아 일반 사용자용 댓글 서비스 전체를 개통 완료로 표시할 수 없다.** 기존 승인된 계정이 있으면 구현된 로그인 경로를 사용할 수 있지만, 이번 작업에서 일반 가입이나 운영자 권한을 새로 열지 않았다.

개통 후에는 승인된 작성자·다른 독자·운영자 계정으로 휴대폰에서 대기 댓글의 비공개, 승인 후 새로고침 공개, 삭제·신고·차단, 로그아웃 후 이전 댓글 비노출을 최종 확인한다. 기존 하늘·관측·학습·로컬 꾸미기는 로그인 없이 계속 사용할 수 있다.
