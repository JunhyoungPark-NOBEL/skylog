## 1. 목표

폰을 하늘로 들면 **폰 뒷면이 향한 하늘**이 화면에 보이고, 폰을 돌리면 지연 100ms 이내로 따라온다. 나침반 오차는 **별 정렬 보정**으로 1~2° 수준까지 줄일 수 있다. 위치는 GPS 또는 저장된 관측지에서 온다. 권한 요청·미지원 안내가 친절하다.

## 2. 범위

## 3. 요구사항

### MUST

1. **위치** (`sensors/geolocation.ts`, `locationStore`)
   - `navigator.geolocation.getCurrentPosition` → `watchPosition`(정확도 개선 시 갱신, 100m 이내면 중단). 권한 거부/미지원/타임아웃 각각 다른 안내. 마지막 위치를 저장해 오프라인에서 사용.
   - 관측지 관리(`features/settings/Sites.tsx`): 목록(기본 프리셋 "대전(KAIST 부근)" + "현재 위치"), 추가(이름·위도·경도·고도·Bortle), 편집·삭제, 기본 지정. 저장은 Dexie `sites`(T0에서 생성됨). 위도/경도는 십진수 입력 + 붙여넣기 파서("36.37, 127.36", "36°22′N 127°22′E").
   - **보이는 하늘 범위(C15)**: 관측지 편집에 방위 링 위에서 보이는 구간을 드래그로 지정하는 **하늘 구역 선택기**(예: 베란다 → 남동~남서 [[110, 250]]) + 최소 고도 슬라이더(건물에 가려지는 높이, 기본 0°). `Site.visibleAz`, `Site.minAltDeg`에 저장. 하늘 화면에서 범위 밖 영역을 살짝 어둡게 표시하는 토글(선택). T3의 추천·오늘의 천체가 이 값을 **하드 필터**로 쓴다.
   - 상단 상태 바에 관측지 이름과 GPS 정확도 표시.

2. **방향 센서 어댑터** (`sensors/orientation/`) — 어댑터 패턴, 런타임에 최선의 것을 선택
   - `AbsoluteOrientationSensorProvider`(Generic Sensor API, Chrome/Edge Android): 쿼터니언 직접 사용. 권한 정책·보안 컨텍스트 확인.
   - `DeviceOrientationAbsoluteProvider`(`deviceorientationabsolute` 이벤트, Android): alpha/beta/gamma → 쿼터니언.
   - `DeviceOrientationProvider`(`deviceorientation`, iOS·기타): alpha는 **상대**(기기 시작 기준). iOS는 `webkitCompassHeading`(0=북, 시계 방향)과 `webkitCompassAccuracy`를 함께 제공 → **yaw 동기화** 방식으로 절대 방향을 복원(§4.2).
   - iOS 13+: `DeviceOrientationEvent.requestPermission()`은 **사용자 탭 핸들러 안에서만** 호출 가능 → "AR 모드 시작" 버튼에서 호출. 거부하면 그 브라우징 세션 동안 다시 물을 수 없고, iOS 13 이후에는 설정 앱에 관련 토글이 **없다** → 안내 문구: "Safari 탭(또는 홈 화면 앱)을 완전히 닫고 다시 연 뒤 AR 버튼을 눌러 주세요. 그래도 안 되면 설정 > Safari > 고급 > 웹사이트 데이터에서 이 사이트 데이터를 삭제 후 재시도."
   - 공통 출력: `{ q: Quaternion(기기→ENU 세계), headingSource: 'absolute'|'compass-sync'|'manual', accuracyDeg?: number, timestamp }`. 화면 방향(`screen.orientation.angle`)을 보정에 포함.

3. **기기 자세 → 카메라** (`sensors/orientation/toCamera.ts`)
   - Three.js `DeviceOrientationControls`(구 예제)의 변환을 참고해 **우리 씬 프레임(+X 동, +Y 천정, +Z 남)** 에 맞게 구현. 의미: 카메라는 **폰 뒷면(후면 카메라)이 향한 방향**을 본다.
   - 테스트 벡터(필수, Vitest): `alpha=0, beta=90, gamma=0`(폰을 세워 화면이 나를 향하고 뒷면이 북쪽) → 카메라가 **북쪽 지평선**(alt 0, az 0). `beta=0`(폰 평평, 화면 위) → 천저(alt −90). `beta=180`(화면 아래로, 뒷면 하늘) → 천정. `alpha=90, beta=90` → **서쪽** 지평선, `alpha=270, beta=90` → **동쪽** 지평선. 여기가 가장 자주 틀리는 곳이다: W3C 규약상 **alpha는 위에서 볼 때 반시계 방향으로 증가**(절대 모드에서 기기 상단이 북쪽이면 0, 서쪽이면 90, 동쪽이면 270; 즉 나침반 heading = 360 − alpha). 부호 규약을 주석과 ARCHITECTURE에 적고, 화면 회전 90°/270°에서도 같은 결과가 나오는지 테스트한다.
   - 롤(gamma)로 화면이 기울어지면 하늘도 같이 기울어진다(실제 AR처럼). 설정으로 "수평 유지" 옵션.

4. **융합·필터** (`sensors/orientation/filter.ts`)
   - 쿼터니언 저역통과(slerp, 시간 상수 ≈ 80~120ms) + 미세 떨림 데드밴드(0.2°) + **적응 이득**: 각속도 > 30°/s이면 이득 1.0(즉시 추종), 정지에 가까우면 시간 상수대로. 이벤트 주기(≈ 60Hz)와 렌더 루프 분리. 측정 가능한 목표: 90° 스텝 입력 후 최종 방향 2° 이내 도달 ≤ 150ms, 정지 시 잔여 떨림 < 0.2°.
   - `absolute` 소스 사용 시에도 나침반 노이즈가 크므로 **yaw만 더 강하게** 평활(시간 상수 500ms), 자이로에서 오는 pitch/roll은 빠르게.
   - 자기장 이상 감지: 짧은 시간에 heading이 15° 이상 튀면 "나침반 간섭 의심" 경고 배지(금속·자석 케이스 안내).

5. **보정(캘리브레이션)** (`sensors/orientation/calibration.ts`, 순수 함수)
   - 모델: `q_world = R_yaw(δ) · q_sensor`. δ는 **세계 프레임 yaw 오프셋**(나침반 오차 + iOS 상대 alpha 기준점 + 잔여 편각 오차). 별 정렬이 있으면 별 정렬이 최종 보정.
   - **자기 편각(MUST)**: Android의 절대 방향(`AbsoluteOrientationSensor`/`deviceorientationabsolute`)은 **자북 기준**이다. 대전은 2026년 편각 ≈ 8~9° W이므로 보정하지 않으면 AR 화면이 그만큼 틀어져 "앱이 고장났다"로 보인다. WMM 계수 기반 라이브러리(WMM2025 계수인지 실행 시 확인; 없으면 계수 파일을 직접 포함)로 관측지·날짜의 편각을 계산해 절대 소스에 기본 적용(`진북 = 자북 + 편각`, 동편각 +, 서편각 −; 부호 테스트 포함: 대전 → 진북 방위 = 자북 방위 − 8.x°). iOS `webkitCompassHeading`은 위치 서비스가 켜져 있으면 이미 진북 기준일 수 있으므로 iOS는 기본 **미적용**(G1 결과·실기기 3-자세 프로토콜로 확정). 적용된 편각 값을 디버그 패널과 상태 바 툴팁에 표시하고, 설정에서 끌 수 있게.
   - **1-별 정렬**: 사용자가 화면 중앙 십자에 밝은 별(또는 행성·달)을 맞추고 그 천체를 선택 → 현재 센서 방향과 천체 실제 alt/az의 **방위 차이**를 δ로 저장(고도 차이는 pitch 오프셋으로 별도 저장, 보통 작음). 저장 위치·시각·정확도 표시. 재정렬은 언제든.
   - **자동 후보 제안**: 지금 하늘에서 고도 20~70°, 등급 ≤ 1.5인 천체와 행성·달을 정렬 대상으로 추천(북극성은 항상 후보).
   - **수동 미세 조정**: 화면 좌우 드래그로 δ를 ±0.5° 단위 조정(센서 모드에서 드래그 = 보정으로 해석), 고도는 상하.
   - 보정 상태 표시: 상단에 "보정됨 (베가, 3분 전)" / "미보정(나침반)" 배지.

6. **AR 모드 UX** (`features/sky/ArToggle.tsx`)

### 4.2 iOS yaw 동기화 — "같은 물리 축"을 비교한다

`deviceorientation`의 (alpha, beta, gamma)로 상대 쿼터니언 `q_rel`(기기→임의 yaw 기준의 세계)을 만든다. `webkitCompassHeading`은 **기기의 특정 물리 축**(일반적으로 화면 상단 방향 +Y 축을 수평면에 투영한 방위로 알려져 있으나, 확정은 §7의 3-자세 프로토콜로)의 방위다. 따라서 동기화는 반드시 **같은 축의 방위끼리** 비교한다:

1. `compassAxis: 'top' | 'back' | 'yaw'` 설정(기본 `'top'`, G1·실기기 결과로 확정).
2. `q_rel`로 그 축(예: 기기 +Y)을 세계 프레임으로 회전시켜 수평면에 투영 → `az_rel(axis)`.
3. `δ_sync = wrap180(compassHeading − az_rel(axis))`, `q_world = R_yaw(δ_sync) · q_rel`.
4. 갱신 조건: `webkitCompassAccuracy ≤ 15°`, **그리고 그 축의 수평 투영이 잘 정의되는 자세일 때만** — 상단 축 기준이면 폰이 **눕거나 완만히 기운 자세(beta 15°~65°)** 에서만. 폰을 세우면(beta≈90°) 상단 축이 천정을 향해 방위가 정의되지 않고, 하늘을 향해 더 젖히면(beta > 90°) 상단 축의 방위가 뒷면 방위와 **180° 반대**가 되므로 이 구간에서는 δ_sync를 갱신하지 않고 자이로 상대 회전만 쓴다.
5. δ_sync는 지수 평활(시간 상수 ≈ 3초), 튀는 값(15°/초 이상)은 무시. 별 정렬 δ가 생기면 그것이 최종 보정(δ_sync 갱신 중단, "보정됨" 상태).

이 설계는 `compassAxis`가 무엇이든 같은 축을 비교하므로 안전하며, 잘못 가정하면 폰을 세우는 순간 하늘이 180° 뒤집히는 증상으로 즉시 드러난다(§7 체크리스트에 포함).

### 4.3 데스크톱 시뮬레이터

`SensorSimProvider`: 슬라이더(alpha 0~360, beta −180~180, gamma −90~90, compassHeading, accuracy) 값을 같은 인터페이스로 발행. Playwright 테스트가 이 Provider로 AR 모드 전 과정을 자동 검증한다(권한 프롬프트 없음).

- [ ] 편각: 대전 좌표에서 계산된 편각이 −8~−9° 범위(부호 테스트), 절대 소스에만 적용, 디버그 패널에 표시.
- [ ] 관측지 "보이는 하늘 범위" 선택기 저장·표시 동작.
- [ ] 디버그 패널 덤프 복사 동작.
- [ ] 배포 후 **실기기 체크리스트**를 사용자에게 전달(§7). 사용자 결과 반영 전에는 완료 보고에 "실기기 검증 대기"로 표시하고, 결과 반영 세션에서 최종 완료.
- [ ] 태그 `task-2-done`(실기기 반영 후).

## 7. 실기기 테스트 체크리스트 (사용자에게 그대로 전달)

기기·OS·브라우저 버전을 적어 주세요. 밝은 별이 보이는 밤이 아니어도 낮에 태양·달·건물 방위로 확인 가능합니다.

- [ ] AR 켜기 → 권한 프롬프트가 뜨고 허용 후 하늘이 움직임을 따라오는가 (지연 체감: 좋음/보통/나쁨)
- [ ] 폰을 **북쪽**(지도 앱으로 확인)으로 세우면 화면 중심 방위가 N±10° 안인가 → 디버그 패널 덤프 복사해 붙여넣기
- [ ] **3-자세 프로토콜(iOS 필수, Android도 권장)**: 멀리 있는 랜드마크(방위를 지도로 확인)를 향해 폰 뒷면을 두고 ① 폰을 45° 정도 눕힌 자세 ② 세운 자세(90°) ③ 하늘 쪽으로 더 젖힌 자세(120°)에서 각각 디버그 덤프(compassHeading, alpha, 화면 중심 방위)를 복사해 주세요. 세우는 순간 하늘이 180° 뒤집히는지 여부도 적어 주세요.
- [ ] 폰을 눕혀 화면을 위로 하면 천저(땅), 뒤집어 하늘로 향하면 천정이 보이는가
- [ ] (폰만 들고, 광학 기기 없이) 낮이면 태양, 밤이면 달/밝은 별을 십자에 맞춰 **1-별 정렬** → 다른 방향의 천체(달·행성)가 십자 안에 오는가(오차 대략 °). ※ 망원경·쌍안경에 폰이 붙어 있을 때는 절대 태양을 쓰지 않는다(T5).
- [ ] 손으로 드래그 → "수동" 표시 → 5초 후 센서 복귀
- [ ] 금속 책상/자석 근처에서 간섭 경고가 뜨는가
- [ ] 화면 회전(가로)에서도 방향이 맞는가 · 10분 사용 후 발열/배터리 체감
- [ ] (iOS) 권한을 한 번 거부한 뒤 안내 화면이 뜨는가

## 8. 산출물 & 인수인계

- 완료 보고 + STATUS + DECISIONS(Provider 우선순위, 편각 기본값, 필터 상수, iOS 동기화 방식). `docs/TESTING.md`에 실기기 절차 반영.
- T5용 API: `calibration.ts`의 `solveYawOffset(samples)`, `applyOffset(q, δ, pitchOffset)`은 T5에서 "폰-경통 정렬"로 확장되므로 인터페이스를 일반화해 둔다(§T5 4.1 참고).
- 사용자 액션: G1 산출물이 아직 없으면 T5 전까지 실행 권고, **G4**(수학 리뷰)는 T5 후 한 번에.

## 9. 주의/금지

- 권한 요청을 페이지 로드 시 자동으로 하지 말 것(iOS에서 영구 실패). 센서 이벤트 리스너는 AR 모드에서만 등록, 벗어나면 해제(배터리).
