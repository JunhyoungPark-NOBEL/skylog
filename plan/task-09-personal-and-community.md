# T9 — 내 마당과 모두의 사진

## 목적과 범위

2026-09-08 사용자 요청: 전 기능을 무료로 제공하고, 후속 설계의 꾸미기·사진·댓글·개인 백업을 실제 구현한다. 다섯 하단 탭은 유지한다. 서버 계정 가입·인증은 사용자가 진행하며, 프로젝트가 연결되기 전 온라인 기능을 연결된 것처럼 표시하지 않는다.

## 실행 순서

1. 내 마당: 로컬 아바타, 다섯 자리의 장식, 기존 업적에 따른 영구 보상. 백업에 포함하고 잘못된 가져오기 값을 정규화한다.
2. 사진: 대상별 갤러리 → 사진 상세 → 댓글. 공개 전에 대상·사진·공유 동의를 확인한다. 원래 관측 기록은 자동 공개하지 않는다.
3. Supabase: 인증, 비공개 저장소, RLS, 검토 대기 게시물·댓글, 신고·차단·이의 신청·운영자 검토, 계정 삭제.
4. 개인 클라우드 백업: 명시적으로 저장·복원한다. 관측 위치가 들어 있는 백업과 공개 사진 저장소를 분리한다. 양방향 자동 동기화로 표현하지 않는다.
5. SQL 권한 검사, 기존 테스트, 새 화면의 좁은 화면·영어·키보드 검사 후 배포한다.

## 인수 기준

- 결제·광고·구독·가격 표시 없이 기본 꾸미기와 업적 보상을 이용한다.
- 보상 중복 발급이 없고 기존 기록·학습·백업을 보존한다.
- 공개 사진은 재인코딩하여 EXIF를 제거한다. 미검토 사진과 댓글은 다른 일반 계정에 보이지 않는다.
- 작성자·다른 사용자·운영자의 읽기/쓰기 권한을 실제 PostgreSQL에서 검사한다.
- 신고·차단·삭제·검토 경로가 UI와 서버 양쪽에서 동작한다. 서비스 키는 클라이언트에 없다.
- 회원 가입 없이 하늘·학습·로컬 꾸미기를 사용한다. 온라인 연결 실패는 재시도 가능한 상태로 표시한다.
- 서버 연결 및 실계정 검증이 끝나지 않았으면 이를 미완료로 기록한다. 운영자 지정과 메일 발송 설정까지 확인해야 공개 커뮤니티를 개통한다.

## UI 참고와 적용

- [Finch 시작 안내](https://help.finchcare.com/hc/en-us/articles/42149821015693-New-User-Guide): 작은 행동 뒤 보상, 꾸미기를 별도 화면에 둔다. 유료 상점은 도입하지 않는다.
- [Google Photos 공유 관리](https://support.google.com/photos/answer/9789702?hl=en): 공개 대상을 확인하고 상세 화면에서 댓글과 공유 설정을 관리한다.
- [Strava 모바일 클럽](https://support.strava.com/en-us/articles/15401837-clubs-on-the-mobile-app): 대상별로 모으고 콘텐츠와 설정을 분리한다.
- [Material 목록–상세 구성](https://m3.material.io/foundations/layout/canonical-examples/overview): 한 번에 한 단계씩 노출한다.
- [Apple 탭 바](https://developer.apple.com/design/human-interface-guidelines/tab-bars): 상위 목적지를 안정적으로 유지한다.

위 사례의 정보 구조를 참고하며 캐릭터·이미지·상표는 복제하지 않는다. Material/Apple 문서는 검색 및 문서 구조를 참고했으며 JS 전용 예시 화면의 시각 검토를 완료했다고 주장하지 않는다.
