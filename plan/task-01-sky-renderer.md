# Task 1 — 천구 렌더러 (Stellarium식 하늘 뷰, 수동 조작·시간 제어·오버레이)

> 실행 전 읽기: `plan/00-master-plan.md`, `plan/STATUS.md`(T0 완료 보고), `docs/ARCHITECTURE.md`(팩 포맷·행렬 API)
> 선행: T0 완료. 예상 분량: 세션 1~2개.

## 0. 세션 시작 절차

1. STATUS 확인 → 저장소 최신화(`git pull`) → `pnpm install && pnpm test`로 T0 상태가 건강한지 확인.
2. 이 프롬프트 §3의 MUST를 순서대로. 렌더러는 **데스크톱 브라우저에서 마우스로 완전히 검증 가능**해야 한다(센서는 T2).
3. 각 단계마다 Playwright 스크린샷을 찍어 세션이 직접 본다(예: 대전 2026-09-06 21:00 KST 남쪽 하늘에 여름 대삼각형이 높이 떠 있고, 궁수자리가 남서쪽 낮게, 페가수스 사각형이 동남쪽에 있어야 함). 수치 비교는 마스터 플랜 §8(b)의 **기준 표**(`tests/fixtures/reference-altaz.json`: JPL Horizons 또는 사용자가 Stellarium에서 읽은 값)로 한다 — 세션은 Stellarium Web을 직접 열 수 없다.

## 1. 목표

폰(또는 데스크톱)에서 **현재 위치·시각의 하늘**이 정확하게 그려진다: 별(밝기·색), 행성·달(위상)·태양, 별자리 선·경계·이름(반투명 오버레이, 토글), 지평선·방위(동서남북)·고도방위 격자, 은하수, 박명에 따른 하늘색. 손가락/마우스로 끌어 둘러보고, 핀치로 확대(FOV 110°→3°), 탭으로 천체를 선택하면 이름이 뜬다. 시간 슬라이더로 시간을 앞뒤로 돌릴 수 있다. 야간 모드에서는 렌더러까지 전부 적색.

## 2. 범위

- In: `src/render/*`, `features/sky/*`, 시간 제어 UI, 선택(hit-test)과 최소 라벨, 레이어 토글 패널, 성능 최적화.
- Out: 센서 기반 카메라(T2), 검색/상세 시트(T3 — 단, 선택 시 이름·등급·alt/az를 보여주는 **작은 툴팁**은 여기서), ★ 마커(T4), FOV 원(T5).

## 3. 요구사항

### MUST

1. **씬 구성** (`render/SkyScene.ts`)
   - Three.js `PerspectiveCamera`가 원점에 있고, 모든 천체는 반지름 R=100의 천구 위 방향 벡터로 배치. 씬 프레임은 마스터 플랜 §6.2(+X 동, +Y 천정, +Z 남).
   - 프레임마다 `eqjToSceneMatrix(time, observer)` 1개를 계산해 **별·별자리·DSO·은하수**의 `uniform mat3`로 전달. 별 좌표는 J2000 단위벡터 버퍼(팩 그대로) — CPU에서 별을 하나씩 변환하지 않는다.
   - 행성·달·태양은 프레임(또는 1초)마다 `bodies.ts`로 apparent alt/az를 계산해 배치(굴절 포함). **굴절은 모든 레이어에 동일하게**: 별·별자리 선·경계·DSO 심볼·은하수는 T0의 공용 GLSL 청크(`refraction.glsl`, Sæmundsson)를 버텍스 셰이더에서 적용하고, HTML 라벨·hit-test·FOV 원 등 CPU 쪽은 `astro/refraction.ts`의 같은 함수를 쓴다. 지평선 근처(고도 2°)에서 별·선·라벨·행성이 서로 떨어지지 않는지 스냅샷 테스트.
   - 렌더 루프: 변경이 있을 때만 그리는 `invalidate()` 패턴(정지 상태에서 GPU/배터리 절약). 시간 진행 모드에서는 초당 1회 이상 갱신.

2. **별 렌더링** (`render/StarLayer.ts` + GLSL)
   - `THREE.Points` + 커스텀 `ShaderMaterial`. 속성: `position(xyz)`, `mag`, `bv`. 유니폼: `uEqjToScene`, `uPixelRatio`, `uFovDeg`, `uLimitingMag`, `uPalette(night)`.
   - 크기: `size_px = s0 · 10^(−0.2·(mag − m0))`, `s0=3px@m0=0`(기기 픽셀비 반영), FOV가 좁아지면 `s0`를 키움(예: `s0 · (60/FOV)^0.5`, 상한 있음). `size < 1px`이면 크기를 1로 고정하고 알파를 줄인다(서브픽셀 별이 사라지거나 깜빡이지 않게). 최대 크기 상한(예: 14px), 밝은 별(mag < 1.5)은 부드러운 글로우(가우시안 폴오프).
   - 색: B−V → RGB 표(−0.4 청백 ~ 2.0 적색, Mitchell Charity 표 근사)를 셰이더에서 보간. 채도는 설정으로 0~1.
   - 한계등급 `uLimitingMag`보다 어두운 별은 페이드 아웃(기본 6.5, T3에서 "실제 하늘처럼" 모드가 값 공급).
   - 기본 팩(≤6.5)로 시작, FOV < 20°가 되면 `stars-deep` 팩을 지연 로드해 교체(로드 중에도 끊김 없음).

3. **행성·달·태양** (`render/BodyLayer.ts`)
   - 행성: 스프라이트 + 라벨. 크기는 등급 기반 별과 같은 규칙에 최소 크기 보장(행성은 항상 찾기 쉽게). FOV < 5°에서는 실제 각지름을 반영한 원반(토성은 고리 타원 힌트: `ring_tilt`로 납작한 타원).
   - 달: 작은 `SphereGeometry` + Lambert 재질 + **태양 방향 DirectionalLight** → 위상이 물리적으로 자동 생성. 실제 각지름(≈0.5°)이 기본이나 "달·행성 확대 표시" 설정(×3)을 제공. 지구조(earthshine) 약한 앰비언트.
   - 태양: 원반 + 글로우. 태양이 지평선 위면 하늘 밝기(아래 6)에 반영.

4. **오버레이 레이어** (모두 토글 + 투명도 슬라이더, 설정 저장)
   - 별자리 선: `LineSegments`, 큰 원 보간(세그먼트 > 3°면 slerp로 분할). 기본 알파 0.35.
   - 별자리 경계: 점선 느낌(대시 셰이더 또는 세그먼트 간격), 알파 0.2.
   - 별자리 이름: 라벨 위치에 HTML 라벨(한/영 설정), FOV에 따라 표시 개수 제한.
   - 고도-방위 격자(10° 간격), 천구 적도, 황도, 자오선 — 각각 토글.
   - **지평선과 방위**: 지평선 아래는 반투명 어두운 "땅"(설정으로 투명/불투명), 지평선 링에 N/E/S/W(또는 북/동/남/서) + 30° 간격 눈금. 땅 토글 시에도 방위 라벨은 남는다.
   - 은하수: NASA SVS Deep Star Maps 2020의 **별을 제거한 은하수 전용 이미지**(파일명은 SVS 페이지에서 확인; 별이 포함된 starmap 변형은 우리 별 스프라이트와 이중으로 그려지므로 금지) 또는 d3-celestial `mw.json` 중 하나로 구현(선택 근거 DECISIONS). 텍스처 방식이면 2k 등적색 이미지를 안쪽에서 보므로 u를 반전, 방향 검증(궁수자리 쪽이 가장 밝고, 오리온이 은하수 가장자리에 걸치며, 적경이 올바른 쪽으로 증가).
   - DSO 심볼: 카테고리별 기호(은하 타원, 산개 점선 원, 구상 십자 원, 성운 사각) — FOV·등급 기준으로 표시 개수 제한. 메시에는 항상 FOV ≤ 60°에서 표시.

5. **카메라·조작** (`render/CameraController.ts`)
   - 상태는 `viewStore`(centerAlt, centerAz, fovDeg). 드래그(터치/마우스)로 alt/az 이동(감도는 FOV에 비례), 핀치/휠로 FOV **3°~110°**(짧은 변 기준; 이 문서의 모든 FOV는 이 정의를 따른다. 비선형: 넓을수록 빠르게). 관성 스크롤(짧게). 천정/천저 근처 짐벌 처리(alt ±89.5° 클램프, 롤 0 유지).
   - 더블탭: 그 지점을 중심으로 FOV 절반. 두 손가락 탭: FOV 2배(있으면 좋음).
   - `flyTo(altAz | objectId, fovDeg?)`: 부드러운 slerp 애니메이션(300~600ms). T3의 "하늘에서 보기"가 이 API를 쓴다.
   - 화면 방향(portrait/landscape) 변경 시 종횡비 갱신.

6. **하늘 배경 & 대기**
   - 태양 고도에 따른 배경 그라디언트: > 0° 낮(하늘색, 별 대부분 숨김), 0~−6° 시민박명(주황→남색), −6~−12°, −12~−18°, < −18° 완전 어둠. 지평선 방향(태양 쪽)이 더 밝은 간단한 편향.
   - 대기 소광: 고도 < 20°에서 별 밝기를 약간 낮춤(설정 토글, 기본 on).
   - 야간 모드: 팔레트를 전부 적색 계열로(별 색 무시, 밝기만). 배경은 순검정.

7. **시간 제어** (`features/sky/TimeBar.tsx`)
   - 하단 슬라이더(±12시간, 1분 단위), 날짜 선택, 배속(1×/60×/600×/−), "지금" 버튼. 실시간이 아닐 때 상단 상태 바에 눈에 띄게 표시(색 변경 + 시각). 상태는 `clockStore`.

8. **선택(hit-test)과 툴팁**
   - 탭 지점에서 반경 ~24px 안의 별/행성/DSO 중 `가중치 = 화면거리 − k·(밝기)`로 가장 좋은 후보 선택. 선택 마커(원)와 툴팁: 이름(ko/en), 종류, 등급, 현재 alt/az, 별자리. "자세히"는 T3에서 연결(지금은 비활성 버튼).
   - 선택 상태는 `selectionStore`에 저장(T3·T4·T5가 사용).

9. **라벨 시스템** (`render/Labels.ts`)
   - HTML 오버레이(절대 위치 div 풀). 우선순위: 선택 > 행성·달·태양 > 고유명 별(FOV별 등급 임계: FOV 100°→ mag ≤ 1.5, 60°→ 2.5, 30°→ 3.5, ≤10°→ 모든 고유명) > 메시에 > 별자리 이름. 최대 60개, 간단한 겹침 회피(그리드 점유). 화면 밖은 렌더하지 않음.

10. **성능**
    - 60fps 목표(데스크톱), 폰은 ≥ 45fps(T8에서 실측). 불필요한 리렌더 방지(React 상태와 렌더 루프 분리: 스토어 구독은 루프 밖 ref로).
    - 첫 하늘 표시까지 ≤ 2초(캐시 후). 데이터 로드 중 스켈레톤.

### SHOULD

- 넓은 FOV(> 90°)에서 원근 왜곡이 심하므로 **스테레오그래픽 투영 옵션**을 버텍스 셰이더에 구현(카메라 방향 기준 투영을 직접 계산). 어렵다면 FOV 상한을 100°로 낮추고 DECISIONS에 기록.
- 별자리 선 **하이라이트**: 선택한 별의 별자리 선을 밝게.
- 유성우 복사점 마커(활동 기간 중에만, 데이터는 T0 `meteors.v1.json`).
- 화면 상단에 현재 시야 중심 alt/az·FOV·방위 텍스트(디버그 겸 유용).

### COULD

- 별 반짝임 없음(의도적으로 제외). 별자리 그림(D10)은 하지 않는다.
- 스크린샷 저장 버튼(캔버스 → PNG).

## 4. 기술 사양 메모

- `PerspectiveCamera.fov`는 **세로** FOV다. 사용자 노출 FOV는 짧은 변 기준으로 정의하고 변환해 둔다.
- 별 굴절을 셰이더에서 하려면 씬 벡터의 y(=sin alt)로 참 고도를 구해 Sæmundsson 굴절량을 더하고 벡터를 재구성(고도 < −2°는 보정 없음). 행성은 CPU에서 `Horizon(..., 'normal')`. 두 규칙이 지평선 근처에서 눈에 띄게 어긋나면 안 됨(테스트: 같은 alt의 가짜 별과 행성이 같은 y에 그려지는지 스냅샷 비교).
- 시간·장소가 바뀔 때만 행렬 재계산. 실시간 모드에서는 1초에 1회로 충분(별 회전 15″/s).
- HTML 라벨은 `transform: translate3d`로만 이동(레이아웃 스래싱 금지). 라벨 텍스트는 `will-change` 최소화.
- Three.js 예제 `DeviceOrientationControls`는 T2에서 참고. 여기서는 `OrbitControls`를 쓰지 말고 alt/az 기반 자체 컨트롤러를 작성(천구 안쪽에서 보는 모델과 맞지 않음).
- WebGL 컨텍스트 손실 처리(`webglcontextlost` → 재생성), 탭 백그라운드 시 루프 정지.

## 5. UI/UX 지침

- 하늘 위 UI는 반투명 유리 느낌 최소 요소: 좌상단 레이어 토글 버튼, 우상단 설정, 하단 시간 바(접힘 가능), 상단 상태 바(위치·시각·모드).
- 레이어 패널: 별자리 선/경계/이름, 격자, 황도·적도, 지평선(땅), 은하수, DSO, 라벨 언어, 대기 효과, 별 채도, 확대 표시. 각 항목에 투명도 슬라이더(선·경계·이름).
- 야간 모드는 여기서 **완성**: 스크린샷에 적색 외 색이 없어야 한다.

## 7. 테스트

- 자동: 위 테스트 + 스크린샷 확인. 회귀용 스냅샷은 시각·장소 고정(`clockStore` 수동 모드로 주입).
- 실기기(사용자): 폰에서 드래그·핀치 반응성, 글자 크기, 야간 모드 가독성, 배터리 체감(10분 사용).

## 8. 산출물 & 인수인계

- 완료 보고 + STATUS/DECISIONS(투영 방식, 은하수 구현 방식, 라벨 임계값). ARCHITECTURE에 렌더 파이프라인 그림(텍스트) 추가.
- T2를 위한 훅: `CameraController`가 외부 쿼터니언 입력(`setOrientationQuaternion(q)`)을 받아 alt/az로 변환하는 진입점을 미리 만들어 둔다(센서 모드 = 이 입력이 매 프레임 들어오는 상태).

## 9. 주의/금지

- 별을 CPU에서 매 프레임 변환하지 말 것. `OrbitControls` 사용 금지. 외부 CDN 스크립트 금지(오프라인).
- 정확도 이슈(거울상, 방위 반전)는 가장 흔한 실패다: **동쪽이 화면에서 오른쪽인지**(북쪽을 볼 때), **별자리가 거울상이 아닌지**(오리온의 벨트 기울기, 북두칠성 손잡이 방향)를 반드시 스크린샷으로 확인.
