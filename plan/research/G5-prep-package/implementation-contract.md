# T7 구현에 넘길 완료 판정·안전 규약 제안

이 문서는 **구현 제안**이다. 실제 저장소의 데이터 모델이나 이벤트가 아래와 같다고 주장하지 않는다. 첨부 Task7의 JSON 키는 변경하지 않고 필요한 추가 실행 조건은 별도 파일에 보관했다. 해당 조건을 구현하지 못하면 관련 미션·배지를 비활성화해야 한다.

## 콘텐츠와 단계

정식 콘텐츠 인덱스에서 해당 항목이 게시됐고 로드 가능한지 검사한다. 카탈로그에 ID가 있다는 것과 설명 콘텐츠가 게시됐다는 것은 다르다. `read`는 해당 콘텐츠 화면의 로드 성공과 읽기 완료 동작을 구분해 연결한다. 로드 실패를 완료로 처리하지 않는다.

`find`는 하늘 화면에서 목표를 선택한 동작이다. `observe`는 사용자가 실제 하늘 또는 실제 접안 관측을 하고 기록을 저장한 동작이다. `skyPick`, 수동 지도 탐색, 시간 여행, AR 가리키기만으로 `observe`를 만들지 않는다. 관측 평점은 주관적 품질이며, 낮은 점수를 줬다고 직접 본 사실을 취소하거나 성공을 막지 않는다.

기존 관측을 소급 인정할지, 미션 시작 후 새 기록만 인정할지 T7에서 명시해야 한다. 기본 제안은 미션에 연결한 실제 기록 1건 이상이며, 같은 저장 이벤트의 재수신은 중복 집계하지 않는다. 사용자 삭제·수정 시 집계를 다시 계산한다. 알아보지 못한 천체는 ‘시도/미확인’ 기록으로 남길 수 있지만 이 팩의 `observe` 성공으로 세지 않는다.

`observeAny`는 이번 초안에서 사용하지 않았다. 이후 사용할 경우 category별 내부 카탈로그 종류와 매핑하고, count는 같은 천체의 중복 로그가 아닌 서로 다른 정규 ID 수로 계산할지 명시해야 한다. 지평선 아래 대상이나 안전 제외 대상이 자동 대안으로 선택되지 않게 한다.

## 계절과 실행 시각

`mission-runtime-gates.json`은 실행 시 확인해야 하는 계약이다. `season`만으로 오늘 실행 가능이라고 판단하지 않는다. 기획상의 저녁 21~24시, 태양 중심 고도 -12° 이하, 직접 대상의 고도 25° 이상을 실제 위치·날짜에서 다시 평가한다. 여러 대상은 미션의 관측 구간 동안 각각 유효해야 한다. 근사 선별의 26°는 여유를 둔 QA 기준이지 새 Task7 스키마 값이 아니다.

달·행성의 위치는 동적이다. `any` 미션도 모든 밤에 가능하지 않다. 건물·산·구름 때문에 못 보면 미션을 보류하고 다른 대상이나 실내 학습으로 전환한다. 악천후·위험한 지형으로의 이동을 보상 조건으로 만들지 않는다. 달의 명암 경계는 권장 관측 조건이며, 전체 위상을 관측해야 얻는 배지는 이번에 만들지 않았다.

이 팩의 태양은 읽기/퀴즈 전용이다. 낮의 태양·수성·금성 탐색을 자동으로 실행하는 경로를 추가하지 않는다. 출처: [NASA 태양 관측 안전](https://science.nasa.gov/eclipses/safety/).

## 기능 단계

`arMode`는 Task7 스킬 식별자다. G1에서 구분한 센서 하늘 보기와 실제 카메라 영상 합성을 같은 기능으로 가정하지 않는다. 센서 권한 허용만으로 보정 성공을 발생시키지 않는다.

`align1`·`align2`는 실제 정렬 모듈의 성공 결과와 관측자가 맞춘 대상에 연결한다. 스킬 버튼을 누른 것만으로 완료하지 않는다. G4는 코드가 제공되지 않아 아직 수행되지 않았다. 폰을 경통에 고정한 축, 화면 프레임, 자북/진북, 정렬 유효기간은 T2/T5와 합의해야 한다.

`fovSetup`은 실제 장비의 시야각을 저장한 성공에 연결한다. 10×50만으로 고정 시야각을 추정하거나, 90mm 구경만으로 접안 시야를 결정하지 않는다. 이 문장은 장비 설정에 대한 설계 제안이며 특정 제품 사양을 제공하지 않는다.

`sketch`는 스케치 편집기를 열었다는 동작이 아니라, 사용자가 내용 있는 스케치를 저장한 결과다. 선의 정확도나 미술 실력을 평가하지 않는다. `backup`은 내보내기 데이터 생성·정상 종료와 취소를 구분한다. 단순 Promise 반환이 복원 가능성까지 증명하지는 않으며, 원본 삭제를 튜토리얼에 요구하지 않는다.

`checklist`는 자가 확인이지 장비의 안전이나 천문학적 정확도를 자동 검증한 증거가 아니다. 아직 없는 기능을 체크리스트 문장으로 우회해 ‘구현 완료’로 바꾸지 않는다.

## 하늘 선택 문항

스키마의 `answer`는 정규 천체 ID이며, 3°는 구면상의 각거리다. 확대율마다 달라지는 픽셀 반경이나 센서 오차 허용치와 혼동하지 않는다. 텍스트 문항은 해당 별을 실제로 볼 수 없을 때에도 학습 가능하지만, 하늘 선택 문항은 정답이 보이는 유효한 지도 장면에서만 출제한다.

출제 전 전체 표시 목록에서 가까운 별과 달·행성을 검사한다. 다른 밝은 객체가 정답 반경 3° 안에 있으면 문항을 보류한다. 대안 정답 중심의 허용 원이 겹치지 않도록 6° 이격도 확인한다. 현재 7별끼리의 이격만 통과한 것은 전체 하늘 격리 통과가 아니다. `skypick-screening.json`의 미확인 상태를 true로 임의 변경하지 않는다.

실제 탭의 가장 가까운 객체가 다른 별이라면 정답 반경 안이라는 이유만으로 정답 처리하지 않는다. 렌더링된 프레임과 판정에 쓰는 위치·시간을 맞추고, 정답을 노출하는 라벨/선택 하이라이트를 해제한다. 천정과 화면 경계·확대/축소·가로/세로 회전에서 테스트한다.

시뮬레이션으로 푸는 경우 ‘지도 연습’으로 명시한다. 퀴즈 점수는 기록할 수 있지만 실제 관측 수·계절 관측 배지는 증가시키지 않는다. 같은 정답별의 변형 문항은 한 세션에서 최대 하나만 출제하고, 별자리 소속 객관식과 곧바로 정답을 알려 주는 하늘 선택을 연달아 내지 않는다.

## 배지

`rewardBadgeId`는 연결 정보이지 무조건 수여 명령이 아니다. 실제 BadgeRule을 만족했을 때만 수여한다. 여름 대삼각형 미션은 세 별의 `find` 세 건뿐 아니라 `observe` 세 건을 넣었다. 세 별을 탭하거나 콘텐츠를 읽기만 한 경우에는 관측 배지를 주지 않는다.

`quizStreak` 기본 제안은 서로 다른 문항의 최초 응답 연속 정답이다. 동일 문항 재시도로 정답 수를 부풀리지 않고 오답 시 끊는다. 앱을 닫은 시간, 날씨, 날짜가 바뀌었다는 이유로 이 연속 정답을 실패로 처리하지 않는다. 이 의미가 기존 T7과 다르면 데이터/설명과 구현을 함께 바꾼다.

`constellationCount`는 **아직 의미가 확정되지 않았다**. 이 초안 문구는 소속이 다른 길잡이별 관측을 세는 제안이다. T7이 별자리 자체의 observe만 세기로 했다면 이 3배지는 비활성화하고 문구와 미션을 맞춰 수정한다. 규칙 이름만 보고 조용히 다른 집계법을 사용하지 않는다.

`messierCount`는 정규화한 서로 다른 천체 수다. 다른 별칭으로 같은 천체를 여러 번 세지 않는다. 해당 콘텐츠와 미션이 없어 이번에는 보류한다. `firstStarHop`은 성단 튜토리얼과 성공 경로가 준비될 때, `align2Success`는 G4/T5 확인 뒤에 활성화한다.

`streakNights`, `planetsAll`, `moonPhasesAll`은 이번 배지에 넣지 않았다. 연속 밤 관측을 강요하거나, 보이지 않는 삭을 직접 보았다고 기록하게 하거나, 정밀도·장비 한계를 넘는 행성 관측을 의무화하지 않기 위한 설계 선택이다.
