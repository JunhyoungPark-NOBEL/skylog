# G5 사전 작업팩 — 학습 데이터 초안

**작성일: 2026-09-07 / 상태: 사전 편집·검토용, 정식 배포 불가**

코드가 없어도 먼저 할 수 있는 학습 데이터 작성과 정적 검사를 수행했다. G4의 실제 센서·정렬 코드 리뷰를 대신하지 않는다. 정식 `content/v1/index.json`과 실제 Task 7 구현은 제공되지 않았으므로, 이 팩을 앱이 즉시 실행할 수 있다고 인증하지 않는다.

난이도는 1단계 40, 2단계 40, 3단계 20문항이다. 난이도 분류는 편집 판단이며 사용자 시험으로 측정한 결과가 아니다. 객관식 정답은 0부터 시작하는 보기 인덱스이며, 보기와 정답을 함께 섞었다. 참·거짓은 각각 10문항이다.

## 2. 실제로 존재하는 자료와 아직 없는 자료

첨부 G3 배치 1은 20개 **초안**이다. 이 중 `star:HIP24608` 카펠라는 분광형 충돌과 low 표시 때문에 제외했다. 이번 미션의 대상, 퀴즈 대상·정답, read 참조는 나머지 19개 안에만 있다. G2의 별자리 표는 한국어 이름과 IAU 코드의 대조에 사용했다.

121행의 `content-targets.v1.csv`는 **작성 대상 목록**이지 121개 콘텐츠가 모두 게시됐다는 증거가 아니다. 정식 인덱스를 임의로 생성하거나 기존 파일을 `content/v1/index.json`으로 이름만 바꾸지 않았다. ZIP 안의 `inputs/g3-content-draft.json`은 사용자에게 이미 제공된 초안의 사본이다.

별의 V등급 대역 미확인, 카펠라 분광형, 베텔게우스·데네브 등의 거리 검토 사항을 새 정답으로 확정하지 않았다. 정확한 거리 숫자 순위·현재 행성 등급·최신 위성 수는 이 문항에 넣지 않았다. 별자리 소속, 종류, 관측 한계, 위상, 전통 이야기의 범위를 중심으로 작성했다.

문항별 근거는 `evidence-ledger.json`에서 G3 대상·필드와 연결된다. 여기에 들어 있는 상위 출처 URL 모두를 이번에 다시 열어 전수 승인한 것은 아니다. 이번에 별도로 확인한 NASA·한국천문연구원·USNO 문서는 `source-registry.json`에 구분했다. 달의 위상 순서와 위상/월식 구분은 외부 보강 근거를 문항별로 표시했다.

## 3. 튜토리얼과 계절 조건

작성한 필수 튜토리얼은 세 개다.

- `summer-vega-align-one`: `arMode` + `align1`. 센서 허용, 센서 화면, 실제 별 중심 맞춤, 정렬 성공을 구분한다. 카메라 AR 합성이 구현됐다고 가정하지 않는다.
- `summer-vega-fov`: `fovSetup`. 10×50이라는 표기만으로 실제 시야각을 추측하지 않는다.
- `any-moon-first-sketch`: `sketch`. 앱에 저장한 스케치만 성공 이벤트로 취급한다.

네 번째인 **스타 호핑으로 성단 찾기**는 성단의 G3 콘텐츠가 없으므로 보류했다. 알데바란 콘텐츠에 히아데스가 언급된다고 별도의 성단 콘텐츠가 게시됐다고 취급하지 않았다.

`season: any`는 매일 밤·모든 시간에 볼 수 있다는 뜻이 아니다. 연중 미션 4개도 해당 밤에 달이나 목성이 충분히 높을 때만 시작한다. 태양·수성·금성은 직접 관측 미션에서 제외했으며, 태양은 설명·안전 퀴즈에만 사용했다. 태양 필터 관련 안전 근거는 [NASA의 안전 안내](https://science.nasa.gov/eclipses/safety/)를 확인했다.

### 고도 선별 결과

기획상의 대표 관측점을 북위 36.35°, 동경 127.38°로 가정하고 **2026년 매일 KST 21:00~24:00**을 1분 간격으로 선별했다. 실제 사용자 위치나 특정 관측장을 확인한 것은 아니다.

고정별 미션 20개 모두 지정 계절 안에서 `estimatedMinutes` 전체 동안 모든 직접 대상이 **근사 고도 26° 이상**, 태양이 **-12° 이하**인 구간을 찾았다. 원래 요구의 25°보다 1° 여유를 둔 기획용 선별이다. 날짜별 결과와 대표 구간은 `visibility-screening.json`에 있다.

- 초봄 오리온 색 비교는 이 모델에서 **3월 1~17일**에 20분 구간이 잡혔다. ‘봄이면 언제나 가능’으로 배포하면 안 된다.
- 안타레스는 첨부 적위에서 남중고도가 약 **27.22°**다. 같은 선별 조건의 저녁 구간은 **6~7월**에 있었고 8월에는 없었다.
- 달·목성 미션 4개는 이번 근사 계산으로 확인하지 않았으며 **실시간 천체력 계산 대기**다.

계산식은 [USNO 항성시](https://aa.usno.navy.mil/faq/GAST), [고도 변환](https://aa.usno.navy.mil/faq/alt_az), [근사 태양 위치](https://aa.usno.navy.mil/faq/sun_approx)에 근거한다. 입력 RA/Dec의 epoch가 미기재되어 원값을 그대로 사용했고, 세차·장동·고유운동·시차·굴절을 반영하지 않았다. 따라서 이 결과를 앱의 정밀 천체력, 실제 관측 가능 보장 또는 날씨 예보로 사용하지 않는다. 정식 카탈로그 좌표 기준을 확인한 뒤 날짜별 겉보기 위치로 재검증해야 한다.

## 4. 검증 결과와 중요한 제한

`python scripts/validate.py`의 **61개 검사 통과, 오류 0개**를 확인했다. 이 안에는 스키마, ID, 참조, 보기/정답 타입, 계절·장비 균형, 선수 미션 순환, 위험 대상 제외, 고도 선별 결과, 검증기 자체의 변형 입력 검사 8개가 포함된다.

그러나 `python scripts/validate.py --release`는 **의도적으로 실패(exit 2)**한다. 정식 인덱스·실제 기능·원 요구 수량·성단 튜토리얼·하늘 선택 판정·배지 집계 규약 등 9개 보류 사유 묶음을 보여 준다. 구조 검사 통과와 정식 배포 승인, 천문학적 사실의 전수 검토는 다른 상태다.

**하늘 선택은 아직 활성화하면 안 된다.** 7개 정답별끼리는 첨부 좌표에서 최소 약 18.61° 떨어져 있어 반경 3°의 정답 원이 서로 겹치지 않는다. 하지만 첨부 31별 목록은 전천 밝은별 목록이 아니다. HEASARC BSC5P 설명은 확인했으나 수치 테이블 다운로드가 실패하여, 누락된 가까운 별까지 포함한 격리 검사는 수행하지 못했다. 태양계 천체의 근접과 실제 렌더러 판정도 남아 있다.

배지 16개 중 10개는 일반 구현 확인 대기이고, 나머지 6개는 성단/DSO 콘텐츠, 2별 정렬, 별자리 집계 의미 등의 별도 결정이 필요하다. 이 6개는 조건을 무시하고 먼저 수여하지 않는다. `badge-readiness.json`에 개별 사유가 있다.

## 6. 파일 구성과 재현

루트의 `G5-learn-*.json` 네 파일만 Task7 데이터 형식이다. `*.schema.json`은 첨부 스키마의 엄격한 검사용 표현이다. 나머지 파일은 승인·검토 자료이며 앱 데이터에 무조건 병합하지 않는다.

- `Claude-T7-handoff.md`: 전달 문구와 병합 순서.
- `implementation-contract.md`: 관측/정렬/스케치/배지/퀴즈 완료 판정 제안.
- `review-items.md`: 게시 전 검토 목록.
- `quiz-review.md`: 100문항과 실제 정답을 읽는 검토판.
- `G5-learn-codeblocks.md`: 같은 네 JSON 배열의 복사용 코드 블록.
- `validation.json`, `qa/release-check.json`: 실행 결과.
- `inputs/`: 사용한 첨부 자료의 사본. `readiness-manifest.json`에 SHA-256을 기록했다.

```sh
python scripts/validate.py
python scripts/screen_visibility.py
python scripts/validate.py --release
```

검증기는 `requirements.txt`의 jsonschema 환경을 사용한다. 실행된 버전은 검사 결과에 있다. `scripts/build_data.py`는 원본 작성 데이터를 담고 있으며, 실행하면 학습 JSON과 기본 근거/상태 파일을 재생성한다. 문항별 외부 보강 주석도 생성 스크립트에 포함했다. 데이터를 수정한 뒤에는 고도 선별·검증·검토판 생성을 다시 실행해야 한다. 단순 검증에는 build 스크립트를 실행할 필요가 없다.

저장소 커밋, TypeScript 테스트, 실제 앱 UI 조작, 센서·망원경 관측 및 G4 코드 검토는 수행하지 않았다.
